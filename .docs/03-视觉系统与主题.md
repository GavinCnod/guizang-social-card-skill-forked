# 03 视觉系统与主题

本文件讲透三套视觉系统（Editorial Magazine × E-ink / Swiss International / Warm Gold 中登）的硬规则、16 套主题预设、组件与字号规范、背景系统、截图与图片处理工具类，以及三个种子模板的内部结构。它不重复 [04-内容策划与版式骨架](./04-内容策划与版式骨架.md) 里关于 40 个版式骨架（M01-M16、S01-S12、G01-G12）的细节，只回答"为什么长这样、用什么 token、哪些类不能混用"。

阅读基础假设：你已经看过 [README.md](../README.md) 的全局说明，知道本 skill 把一篇已有内容做成小红书 3:4 / 公众号 21:9 + 1:1 封面对。

## 1 三套视觉系统的定位

仓库里没有"按行业选风格"的话题清单。三套视觉系统是**视觉姿态（visual stance）**，不是**内容分类**。任何主题都可以被放进任意一套，决定权在编辑意图："特稿"就用 Editorial，"发版说明 / 系统拆解"就用 Swiss，"需要金色仪式感的盘点 / 榜单"就用 Warm Gold。下面表格只列"典型契合"，不列穷举。

| 视觉系统 | 核心意图 | 典型契合 | 反向契合（不要硬套） |
| --- | --- | --- | --- |
| Editorial Magazine × E-ink | "被偏爱的杂志特稿"的节奏，慢、有氛围、有图证 | 户外、生活方式、反思、人文、文化叙事；职场随笔、AI 评论、产品回顾 | 工程化 KPI 矩阵、纯发版列表、对比测试数据 |
| Swiss International | "国际主义印刷物"的工程节奏：硬网格、纯色块、单一高饱和强调色 | AI 工具、产品更新、工程流程、软件讲解、发版说明、旅行账本、健身数据、菜谱步骤 | 旅行散记、个人情感长文、需要手写感的页面 |
| Warm Gold 中登 | "中登登记纸 + 金墨"的仪式感：paper 底 + 金渐变焦点 + 衬线标题 + 等宽元数据 | 年终盘点、榜单、颁奖、纪念刊、金融复盘、发布里程碑 | 纯工程发版说明、需要极简硬网格的 KPI 页、冷淡感内容 |

切换依据来自 [`references/style-system.md:14-16`](../references/style-system.md)，原文强调"列表只是 good fits，不是 exhaustive"。

### 1.1 选错模式的常见征兆

- 写了一篇情感长文，却套用 Swiss 卡片：会出现"小标题 + 大数字 + KPI 塔"的工科感，丢失原文本意。
- 写了一份工具发版清单，却套用 Editorial：会出现"图片井 + 氛围墨流 + 杂志竖标"，工程感丢失，读者找不到 release note 的硬信息。

两者在硬规则层面互斥：Editorial 必装衬线字体 + 氛围背景，Swiss 禁装衬线字体 + 禁氛围背景。

## 2 Editorial Magazine × E-ink 的设计规则

参考 [`references/style-system.md:18-46`](../references/style-system.md)。

### 2.1 必备元素

| 元素 | 规则 |
| --- | --- |
| 字体 | 标题用衬线（serif-zh），正文用衬线，kicker/meta 才用等宽 |
| 调色 | 暖纸 + 深墨 + 克制中性灰；点缀色极少 |
| 背景 | 必带氛围层（纸纹 / 墨流 / contour field），不允许纯色页 |
| 图像 | 纪实摄影、issue 标签、页码、图注 |
| 节奏 | 大量有目的的留白；细线、杂志栏、图片说明、引语、编辑对比 |
| 纸纹 | 允许，但不能降低正文可读性 |

### 2.2 字体姿态（"越大越细，越小越粗"的非可协商版本）

| 文本 | 字重 | 字距 |
| --- | --- | --- |
| 大尺寸标题（display） | 500 | `+.03em` 到 `+.04em`（宽字距） |
| 小尺寸文本（kicker / meta / label） | 500，等宽大写 | `+.20em` 到 `+.22em`（极宽字距） |
| 正文 | 400，serif-zh（**禁止切到 sans**） | normal |

反模式：如果页面"显得重、显得喊"，问题在标题字重过粗，或者正文切到了 sans。来源 [references/style-system.md:34](../references/style-system.md)。

### 2.3 主题调色硬约束

只允许 [第 4 节](#4-10-套主题预设) 列出的 6 套 Editorial 主题，禁止临时拼暖纸色。`Midnight Ink` 是**唯一允许的深色 Editorial 主题**，仅用于源素材本身已经偏暗的内容（游戏 key art、夜景摄影、电影封面）。不允许造第二套深色主题（[`references/style-system.md:32`](../references/style-system.md)）。

### 2.4 Editorial Identity Test（三项必须同时成立）

来自 [`references/style-system.md:116-124`](../references/style-system.md)。任何一项不满足，都不是真正的 Editorial。

1. 背景必须含至少一层氛围层（纸纹 / 墨流 / 冻结 WebGL / contour field）。整页纯 `#f3f0e8` 不算 Editorial。
2. display 标题必须用 serif-zh / serif-en 字体族（`Noto Serif SC` / `Songti SC` / `Playfair Display`）。
3. 海报至少含以下一种：大幅照片井、带 em-italic 英文的衬线引语、左右 marginalia 栏、带真实杂志行级结构的 ledger。

陷阱：标题是衬线、kicker 全是 mono、药丸栅格结构整齐、背景是纯纸——这是 **Swiss-with-a-serif**，不是 Editorial。要么补氛围 + 杂志结构，要么老实切到 Swiss。

### 2.5 反模式（参考 [`references/style-system.md:127-189`](../references/style-system.md)）

| 反模式 | 现象 | 修正方向 |
| --- | --- | --- |
| A 厚重大标题 | 在 Swiss 里 inline 写 `font-size: 92px; font-weight: 800` | 用 `.h-statement` / `.h-hero` / `.h-xl` / `.num-mega` 等类型化类 |
| B 没有氛围的 Editorial | 单色纸 + 满屏 mono kicker + 单独衬线大标题 | 加纸纹 + 墨流；或 mono 换成 serif / italic；或加大幅照片 / 引语；或切换到 Swiss |
| C 页脚重叠 | `.foot` 绝对定位 bottom，但上面内容涨高压过去 | 用 `display: flex; flex-direction: column; height: 100%` + `margin-top: auto`，或 grid 三行布局。种子模板默认就是 Pattern A |
| D 全屏照片 + 标题压主体 | 渲染时大图盖住海报，标题压在主体像素上 | 走 [第 8 节](#8-文字压图与主体避让) 的"先选图、再构图、最后 tint"流程 |

## 3 Swiss International 的设计规则

参考 [`references/style-system.md:48-80`](../references/style-system.md)。

### 3.1 必备元素

| 元素 | 规则 |
| --- | --- |
| 字体 | Inter / Helvetica Neue / Noto Sans SC 气质 |
| 字重 | 越大越细；小标签更粗 |
| 网格 | 严格 12/16 栏，左对齐，不对称留白 |
| 调色 | 白 / 米白 / 黑 / 克制灰 + **恰好一个**高饱和强调色 |
| 模块 | 直模块、细线规则、无圆角卡片、无阴影、无玻璃拟物 |

### 3.2 字号速查（1080×1440 画板上的经验值）

| 角色 | 尺寸 | 字重 |
| --- | --- | --- |
| 主封面标题 | 84–128 px | 200–400 |
| 页面标题 | 52–82 px | 300–500 |
| 正文 | 28–42 px | 400–500 |
| caption / meta | 20–28 px | 500–650 |

中文标题视觉密度大：**先缩短文案，再缩小字号**。不允许通过缩小正文解决溢出。

### 3.3 Swiss Identity Test（四项必须同时成立）

来自 [`references/style-system.md:106-114`](../references/style-system.md)。

1. 所有大尺寸 display 标题（≥ 72 px on 1080×1440）必须用 [`components.md`](../references/components.md) 列出的类型化类（`.h-hero` / `.h-statement` / `.h-xl` / `.num-mega`），计算后的 `font-weight` 必须 ≤ 300。
2. 文档头部不能加载任何衬线字体族。任何元素不能用 `font-family: serif` 或 `Noto Serif SC` / `Playfair Display`。
3. 章节分隔只能是细线（1–2 px）或网格列距，**不能是卡片边框 + 投影**。
4. 整本只能使用恰好一个强调色主题，不能跨页混用。

任何一项失败 = 这不是 Swiss，是"Swiss-flavored card"，需要修正或重打标签。

### 4.3 Editorial 主题使用守则

- `--paper` 作为主背景，`--ink` 作为主文字。
- `--accent` 克制使用：章节标记、页码、引语规则线、一处高亮短语。
- `--paper-2` 用于照片井、issue strip、checklist 条带。
- 浅色五套：不要做成 beige-on-beige，必须保留真实对比度。
- Midnight Ink：不要在页面上堆不透明卡片 / 色块。深色 Editorial 靠照片出血 + 暖金强调色建立层级，而不是背景色块。

### 4.4 Swiss 四套强调色

所有 Swiss 主题共用同一组灰阶：

| Token | 值 |
| --- | --- |
| `--paper` | `#fafaf8` |
| `--ink` | `#0a0a0a` |
| `--grey-1` | `#f0f0ee` |
| `--grey-2` | `#d4d4d2` |
| `--grey-3` | `#737373` |

只换强调色：

| 主题 | `--accent` | `--accent-on` | 适用 |
| --- | --- | --- | --- |
| IKB Blue（默认） | `#002FA7` | `#ffffff` | AI、技术、产品更新、设计、工程 |
| Lemon Yellow | `#FFD500` | `#0a0a0a` | 年轻、消费、运动、活泼信息 |
| Lemon Green | `#C5E803` | `#0a0a0a` | 生态、未来、新兴科技、健康、荧光当代话题 |
| Safety Orange | `#FF6B35` | `#ffffff` | 工业、警示、紧迫、风险、决策、锐利纠错 |

### 4.5 Swiss 强调色使用守则

- 整本只用一个 `--accent`。
- 禁用渐变、阴影、玻璃拟物、混合强调色。
- 强调色为黄或绿时，文字上色必须用 `--accent-on: #0a0a0a`。
- 优先使用纯色块、细线、网格节奏。

### 5.4 画板自适应

两个种子模板在 `.poster.square` 与 `.poster.wide` 内会自动缩小 display 字号，通常不必手改。除非单个标题已经无法再缩短。

### 5.5 中文标题长度带

中文字符视觉密度大。先按"形状 + 行数"选定档位，再决定字号。

| 标题形状 | Editorial display | Swiss h-hero |
| --- | --- | --- |
| 1 行 ≤ 6 个汉字 | 132 px（默认） | 240 px（默认） |
| 1 行 7–10 字 | 108 px | 200 px |
| 2 行，每行 ≤ 8 字 | 96 px | 180 px |
| 2 行，任一行 9–12 字 | 84 px | 152 px |
| 3 行（少见） | 72 px | 132 px |

仍然放不下：**先缩短文案**。绝对不允许通过缩小正文解决溢出。来源 [`components.md:64-74`](../references/components.md)。

### 5.6 Swiss `.h-xl` 硬上限（每画板已校验）

| 画板 | `.h-xl` 默认 | 行数上限 | 每行字数上限 | 超限后果 |
| --- | --- | --- | --- | --- |
| `.poster.xhs`（1080×1440） | 96 px | 2 | 8 | 3 行会把 ledger / matrix 挤出画板 |
| `.poster.square`（1080×1080） | 88 px | 2 | 7 | 底部卡片或元数据条被裁 |
| `.poster.wide`（2100×900） | 104 px | 1 | 14 | 折行拥挤右侧栏 |

`.poster.xhs` 上若必须 3 行中文标题，参考 [`components.md:86`](../references/components.md)：把版式从 S03/S10/S12（数据密集）切到 S01/S05（封面型）让标题独占。

### 5.7 Editorial `.h-xl` 硬上限

| 画板 | `.h-xl` 默认 | 行数上限 | 每行字数上限 | 超限后果 |
| --- | --- | --- | --- | --- |
| `.poster.xhs` | 88 px | 2 | 9 | 3 行会把 marginalia / ledger / pipeline 推出 issue strip |
| `.poster.square` | 78 px | 2 | 8 | 副段或引语被裁 |
| `.poster.wide` | 96 px | 1 | 16 | 折行拥挤 marginalia 栏 |

### 5.8 最小可读字号（手机降采样后仍能看）

1080×1440 的 PNG 在手机上一般缩到 360–420 逻辑像素宽。低于下表尺寸的文本不可读：

| 角色 | 最小 | 备注 |
| --- | --- | --- |
| 正文 / 段落 | 28 px | Editorial、Swiss 相同 |
| 引语段落（`.lead`） | 30 px | 1.5× 正文的底线 |
| Caption / kicker | 20 px | 不低于 18 px |
| Label / meta 条 | 20 px | 仅 mono |
| 网格单元标题 | 24 px | matrix / brief 卡片 |
| 数字注释 | 22 px | stat-card `.lbl`、ledger `.sub` |

放不下：**先砍文案**。绝对不允许靠缩小字号解决。

### 5.9 图片容器比例类（`.frame-img` / `.frame-shot` 共用）

每个模板的种子都自带 `.r-*` 比例类。**禁止**自己写 `aspect-ratio: 2592/1798` 这类临时比例。

| 类 | 比例 | 用途 |
| --- | --- | --- |
| `.r-3x4` | 3 : 4 | 默认竖版封面与田野照 |
| `.r-1x1` | 1 : 1 | 方形肖像、产品、平衡网格 |
| `.r-4x3` | 4 : 3 | 经典编辑照、顶部出血带 |
| `.r-3x2` | 3 : 2 | 杂志内联图 |
| `.r-16x9` | 16 : 9 | 横版照片、信息图 |
| `.r-16x10` | 16 : 10 | 默认左文 + 右图分栏 |
| `.r-21x9` | 21 : 9 | 公众号 21:9 hero、S08 Image Hero 顶部区 |

`.frame-img` 默认 `object-fit: cover`，`object-position: center 50%`。UI 截图、密集文本、代码、信息图用 `.fit-contain`，不要裁脸或产品关键特征。

### 5.10 `object-position` 必须按主体位置内联写

模板默认只是兜底，**不是推荐值**。每张 `<img>` 都要按主体在原图中的位置内联写：

| 主体位置 | 内联值 |
| --- | --- |
| 主体偏上（天空为主、脸在顶部） | `center 25–35%` |
| 主体居中（默认） | `center 50%`（可省略） |
| 主体中段（徒步者、手部、画面中部） | `center 55–65%` |
| 主体偏下（前景装备、账本、脚部） | `center 70–80%` |

`center 50%` 在 `r-3x4` / `r-21x9` 这种高画面比上会静默把主体裁出去。渲染检查时若主体有超过 1/3 跑出可见裁切框，必须修正。来源 [`components.md:160-169`](../references/components.md)。

### 5.11 Caption 类名（**不要写错**）

| 模板 | 正确类名 | 错例 |
| --- | --- | --- |
| Editorial | `.img-cap`（18 px mono） | `.cap`（会回落到浏览器默认 16 px，触发 R4） |
| Swiss | `.swiss-img-caption`（18 px mono） | `.cap` 同上 |

### 5.12 Swiss 卡片填充类（互斥）

四种类 **不能在同一节点上组合**：

| 类 | 描述 | 用法 |
| --- | --- | --- |
| `.card-ink` | 实心黑墨底，paper 文字 | 唯一一句陈述卡 |
| `.card-accent` | 强调色底，强调色-on 文字 | 整本最多一个强调卡 |
| `.card-fill` | grey-1 底，ink 文字 | matrix / brief / takeaway 网格主力 |
| `.card-outlined` | 透明 + 1 px grey-2 边框，ink 文字 | 需要"卡片感"但不要重量时 |

多卡网格必须用**同一**卡片类，最多允许一个 `.card-accent` 高亮。在同一网格里混 `card-fill` 和 `card-outlined` 会看起来像"随手粘的模板"。来源 [`components.md:131-142`](../references/components.md)。

**Editorial 模板故意不提供卡片类**。Editorial 靠字体、规则线、ledger 行、栏结构建层级，不靠卡片底色。如果你在 Editorial 上想加卡片，几乎一定是模式选错了。

### 5.13 布局原语（两模板共有 / 部分互斥）

| 类 | Editorial gap | Swiss gap | 用途 |
| --- | --- | --- | --- |
| `.stack` | flex column | flex column | 默认竖向流 |
| `.row` | flex row | flex row | 横向流 |
| `.gap-1` … `.gap-5` | 12–64 px | 8–16 px | Editorial 用 px，Swiss 用 token |
| `.gap-6` … `.gap-10` | n/a | 24–64 px | Swiss 独有（Carbon scale） |
| `.col-2-7-5` | 7:5 分栏 | n/a | Editorial 独有，引语 + 图 |
| `.col-2-8-4` | 8:4 分栏 | n/a | Editorial 独有，文字重 + 图 |
| `.grid-12` | n/a | 12 栏 | Swiss 独有 |
| `.span-N` | n/a | grid column span | Swiss 独有 |
| `.grid-3` | 3 列 | 3 列 | 共有 |

### 5.14 图标规则

默认图标库 **Lucide**（仅 Swiss 模板加载）。Editorial 极少用图标，需要时同样用 Lucide，但每张海报限制 1–2 个。

- 不使用 emoji。
- 用棱角分明的 Lucide 图标：`arrow-right` / `check` / `triangle-alert` / `dot` / `plus` / `equal` / `slash`。避免 `smile` / `heart-filled` 这类柔软圆润图标（与 Swiss 几何感冲突）。
- 描边宽度 1.5（Lucide 默认），不要加粗。
- 尺寸：ledger 行指示 56 px、正文内联 32 px、chip 内 24 px。**不低于 20 px**。
- 颜色：`var(--accent)` 高亮、`var(--grey-3)` 中性、`var(--ink)` 主体。**禁用渐变**。

用法：

```html
<i data-lucide="arrow-right" width="32" height="32"></i>
```

Swiss 模板在 `load` 事件中会调用 `lucide.createIcons()`。若在加载后注入图标，需要再手动调一次。

### 5.15 Issue / 角落元数据

社媒卡不像 PPT 有双行页脚 / 页眉元数据，用一个安静元素就够了。

Editorial：

- `.issue-row`：顶部一行，类似 `Vol. 01 · 2026.05`，中间用小强调色圆点分隔。
- `.issue-strip`：底部条，3–5 个短标签用 em-dash 分隔，上方一根细线。

Swiss：

- `.chrome-min`：顶部一行，左分类右日期 / 期数，下方细线。
- `.t-meta`：海报上任意位置的 mono 大写元数据。

**每张海报只用一种 issue 元素**。顶部 issue strip + 底部 issue strip 同时存在会像装饰。

## 6 背景系统

参考 [`references/background-systems.md`](../references/background-systems.md) 与 [`assets/magazine-bg-webgl.js`](../assets/magazine-bg-webgl.js)。

### 6.1 Editorial 分层模型（3–5 层）

1. 主题纸底（来自 [第 4 节](#4-10-套主题预设) 的 `--paper`）。
2. 程序化纸纹（procedural paper grain）。
3. 墨流 / contour field / WebGL fluid canvas。
4. 可选细线结构（仅作为内容分隔，**不是全页背景网格**）。
5. 内容层。

种子模板里这三层已经写好（`.poster > canvas.mag-bg` + `.grain` + `.paper-wash`，外加 `.content`）。`Midnight Ink` 还会自动反色覆盖这三层。

### 6.2 什么时候用强氛围 / 弱氛围

| 强氛围（hero 页、章节页、引语页、稀疏论点页、收束页） | 弱氛围（截图页、密集 ledger、checklist、产品证据页） |
| --- | --- |

如果截图是主证据，背景应当**支持**而不是**竞争**。

### 6.3 WebGL 墨流助手（`assets/magazine-bg-webgl.js`）

对外接口：

```js
window.MagazineBg.mount(canvas, options)
```

| Option | 类型 | 含义 |
| --- | --- | --- |
| `ink` | `[r, g, b]` 0–255 数组 | 墨色（默认 `[0.10, 0.18, 0.12]` 即 `[26, 46, 31]`） |
| `paper` | `[r, g, b]` 0–255 数组 | 纸色（默认 `[0.96, 0.94, 0.90]` 即 `[245, 241, 232]`） |
| `accent` | `[r, g, b]` 0–255 数组 | 强调色（默认 `[0.18, 0.42, 0.31]` 即 `[46, 107, 79]`） |
| `strength` | 0–1 | 整体不透明度（默认 `0.34`） |
| `frozenTime` | number | 传值则冻结画面、不再 RAF；用于截图导出保证稳定 |

模板里读取 CSS 变量 `--ink-rgb` / `--paper-rgb` / `--accent-rgb`（见 [第 4 节](#4-10-套主题预设)），所以切换 `data-theme` 时墨流颜色会自动跟随。

截图导出场景必须用 `frozenTime`，否则多次渲染结果不一致。

### 6.4 降级

如果 `canvas.getContext("webgl")` 失败，脚本会自动回落到 2D 画法：

- 5 个大尺寸径向墨流圆（`ink` / `accent` 交替）。
- 18 条 0.09 不透明度的椭圆 contour。
- 同样吃 `--ink-rgb` / `--accent-rgb`。

返回值里能看到当前模式：`{ mode: "webgl" }` 或 `{ mode: "2d" }`。

### 6.5 禁用清单（背景）

- 禁用亮渐变。
- 禁用全页 grid / dot-matrix / 绘图纸 / 工程图纸背景。
- 禁用无布局关系的装饰 blob / 圆。
- 禁止把强背景标记放在正文文字后面。
- WebGL 不能遮住截图或小 caption。
- **最终图像序列不允许动画**（除非任务是视频）。

## 7 3:4 竖版填充策略

参考 [`references/portrait-fill.md`](../references/portrait-fill.md)。

### 7.1 1080×1440 五段竖向分区

| 区域 | 高度 | 角色 |
| --- | --- | --- |
| Header / meta | 56–90 px | issue 标签、分类、页码 |
| Title / lead | 240–420 px | hook + 主张 |
| Evidence / body | 520–760 px | 图、ledger、对比图 |
| 底部条 | 90–180 px | caption、checklist、总结 |
| Footer | 52–86 px | issue / 页元数据 |

不是每页都用满五段，但每页都要**有意为之的竖向构图**。

### 7.2 填不满的症状

下列任意一项成立都需要重做：

- 表格 / ledger 占画板高度不到 45%。
- 页面下 25% 整片空白，且不是氛围 hero 页。
- 四个列表项渲染成矮行 + 下方大片空白。
- 截图太小，作为证据读不清。
- 正文居中放置，上下没有节奏。

### 7.3 表格太矮的修法

按以下顺序尝试：

1. 行高加到 118–170 px。
2. 加左侧 marginalia 栏，放大数字、关键词或分类标签。
3. 在表格旁加引语栏。
4. 顶部或底部加 2–3 个结果的 issue strip。
5. 把表格换成 M08 Tall Ledger。
6. 如果只有 2–3 个点，改用 M04 Pull Quote 或 M09 Atmospheric Thesis。

### 7.4 文字太稀的修法

- 用 M09 Atmospheric Thesis，把可见 WebGL / 墨流背景开起来。
- 让那句话成为 hero，不要做成小段落。
- 加一行小来源 / 上下文。
- 需要节奏时切到深色 / 墨色页。

### 7.5 7 页小红书组的节奏

至少 5 种不同形状：

- 封面 / feature 图。
- Essay split。
- Tall ledger。
- Evidence screenshot。
- Pull quote 或 Atmospheric thesis。
- Checklist / 对比。
- Closing note。

`title + lead + 3 rows` 的模板在一本里出现不超过两次。

### 7.6 最小占用

主动构图应至少占画板高度的 78%。可计入：

- 大字号。
- 图 / 截图。
- ledger 行。
- hero 页的背景氛围。
- caption 条带。
- marginalia 栏。

有设计的留白是好的，剩出来的空白不是。

## 8 文字压图与主体避让

参考 [`references/image-overlay.md`](../references/image-overlay.md)。两条规则决定一切：先选图再构图，再构图先于 tint。

### 8.1 Rule 1：选图优先，遮罩只在选图失败时用

默认编辑杂志答案是**不加遮罩**。Kinfolk、Cereal、Apartamento、Monocle 几乎不会在大照片上盖均匀黑色渐变。它们靠**选图 + 构图**让文字自然落到 quiet zone 上。如果找不到这样的图，答案是换图，不是用 70% 黑色 scrim 糊一张。

按顺序试，到第一步通过就停。

#### Step 1 — 选图（主杠杆）

两张测试必须都过：

- **Quiet-zone 测试**：画板上至少有一条 ≥ 30% 画板的低细节 / 低对比 / 均匀带（全宽 × ≥ 30% 高，或全高 × ≥ 30% 宽）。示例：散焦背景、深阴影、雾、静水、纯天空、虚化的草。
- **光测试**：照片带**克制 / 大气**的光线——阴天、晨雾、黄金时刻、林下、胶片柔和、黄昏剪影。拒绝正午高饱和、机顶闪光、"游客照"式自拍、通用图库欢快感。

任一测试失败 → 这张照片不适合 M16 Image-Led Cover（满铺大图 + 标题压图）这条线。回退到 M01 split-layout cover，或者重拍 / 重选。**不要"用遮罩修"**。

#### Step 2 — 不加遮罩先构图

把标题放在 quiet zone 里，跑缩略图对比度检查（Step 4）。通过就直接出图。

无遮罩的封面显得有匠心。重遮罩的封面显得"找不到对的图"。每次都先试 Step 2。

#### Step 3 — 局部、取自图色调的 tint（兜底用）

只有 Step 2 对比度检查失败时。三条规则：

1. **局部，不是全画板**。只给标题区打 tint。用 `radial-gradient` 居中标题块，或用单向 `linear-gradient` 淡出到完全透明。**不要**用 `inset: 0` 全画面均匀 alpha 曲线。
2. **取自图色调，不是黑色**。从照片里采样一个深色当 tint 色。森林 → 深苔藓 `#1a2818`。黄昏 → 茶玫黄昏 `#4a2638`。雪 → 冷灰蓝 `#2a3438`。纯黑 `#000` 读起来是"批注层"，不是"氛围深度"。
3. **柔和，不是高不透明**。标题区峰值 alpha 0.15–0.30，向外降到 0。需要 > 0.40 才能读 = 照片没过 Step 1，回去重选。

参考示例（标题在左下，森林色调柔和 tint）：

```css
.hero-bleed::after {
  content: "";
  position: absolute; inset: 0;
  background: radial-gradient(
    60% 45% at 25% 80%,         /* 居中标题块 */
    rgba(26, 40, 24, 0.28) 0%,  /* 森林苔藓色调，柔和峰值 */
    rgba(26, 40, 24, 0.0) 100%);
  pointer-events: none;
}
```

#### Step 4 — 缩略图对比度检查（必跑）

无论是否上 tint：

- 把 PNG 渲出来，缩到 360 px 宽（在 Preview 或浏览器标签页里看）。
- 标题字形不放大也能读清。
- 如果标题"在跟照片打架" → 换照片，或把标题挪到另一块 quiet zone，**不要**加强遮罩。
- 如果照片在均匀深色下显得灰死 → 遮罩太重或盖错区域，从 Step 1 重来。

### 8.2 禁用

- 全画板竖向均匀渐变（早版里的 `rgba(0,0,0,.55) → .10 → .10 → .80` 模式）：那是游戏 key art，不是编辑杂志。
- 纯黑色遮罩色。永远用图色调。
- 标题下方贴一块纯黑 / 纯白矩形：读起来像截图批注。
- `mix-blend-mode: difference`：毁肤色，印刷也废。
- `img { opacity: .6 }`：把照片的深度杀死，正是满铺要的。
- 在用 Step 1 认真试过更好的照片之前就跳到 Step 3。

### 8.3 Rule 2：把文字放离主体 / 脸部

旅行 / 游戏 / 影视 / 穿搭 / 美食经常用真照片做 hero。照片有主体——脸、手、产品、峰。文字压上主体读起来像涂鸦，不像编辑。

#### 主体映射（多模态优先）

设计标题位置前，先打开照片、用 Read 工具观察并用纯语言描述：

1. **主体的脸 / 焦点**在哪？例："登山者的脸在右上三分之一，70% × 30% 附近"。
2. **主体剪影边缘**在哪？例："左边缘在 40% × 收尾，再往下是天空"。
3. **最大开放 / 低细节区**在哪？例："左下四分之一是均匀雾"。

把答案写成 HTML 注释贴在 hero 块旁边：

```html
<!-- subject map (Wukong cover hero):
     face/skull centerpiece: 50% x 45% y, occupies ~30% of frame
     left-side staff & weapons: 15-40% x, full height
     safe text zone: top band (0-15% y) and bottom band (65-100% y)
-->
```

#### 安全区放置（按优先级）

1. **主体上 + 下**（kicker 在顶，标题在底）。90% 的满铺封面应该这么做。
2. **一侧**——如果主体占某一竖列（例如右侧竖肖像），文字填对侧列。配合 Rule 1 Step 3 的局部 tint 只在需要时上。
3. **斜对角**——只在主体在某个角、对角真的空时才用。少见。

**绝不允许 display 标题横穿脸**。90 px 中文标题切过眼睛，即使有遮罩也是破坏性的。

#### 编辑杂志感的构图纪律

- **非对称摆放**：标题偏一侧 / 偏一角，比死居中更自信。Kinfolk / Cereal 的习惯。
- **慷慨的负空间**：标题占画板 ≤ 40%。照片和空 quiet zone 在做设计。
- **一个 quiet zone，只一个**：把标题拆成两个区（顶 + 底）可以；拆三个或绕主体走就乱了。
- **标题永远不压主体剪影**：如果唯一安全的摆位要切过主体边缘，换模式（把照片放进框、二联画、off-image 标题），不要加大遮罩。

#### 裁切守卫（`object-position` 表）

`object-position` 也得跟着主体避让走：

| 主体在原图位置 | 3:4 裁切的 `object-position` |
| --- | --- |
| 脸 / 焦点在上三分之一 | `center 25%`（脸往上抬，给底部标题留空间） |
| 脸 / 焦点在中三分之一 | `center center`（默认，文字走顶 + 底） |
| 脸 / 焦点在下三分之一 | `center 70%`（脸压下去，顶给标题） |
| 宽幅风景，无单主体 | `center 35%`（轻微上抬，保地平线） |
| 竖肖像、整体全身 | `center top` |

#### 放不下的时候

如果主体映射显示没有 ≥ 30% 画板的 safe zone（主体填满画面，比如紧凑肖像），不要硬塞。选项：

- 把照片放进**更小的框**（用 `.frame-img.r-3x4` 或 `.r-1x1`，给它一个明确槽位，外圈留白 + 文字）。
- **两联画**（diptych）：一张紧主体 + 一张负空间，把标题放在负空间那张上。
- **完全把文字挪出图**——标题在上，照片在下。

一张图要吃掉整张画板不意味着文字就该跟它打架，而是文字应该去别处。

### 8.4 交付前清单

每张文字触图的稿件都跑：

- 照片通过 quiet-zone 测试 **且** light 测试。
- 先试过无遮罩构图。tint 只在 Step 4 对比度检查失败后才加。
- 上了 tint：局部（`radial-gradient` 或单向）、图色调（非纯黑）、峰值 alpha ≤ 0.30。
- 没有全画板竖向渐变（`linear-gradient(180deg, rgba(0,0,0,.X) → ...)` over `inset:0`）。
- 主体映射作为注释贴在 hero 块旁。
- 没有 display 标题（≥ 72 px）压在脸 / 手 / 关键产品特征 / 主体剪影上。
- 标题占画板 ≤ 40%，非对称摆放优先于居中。
- `object-position` 从上面那张表里选，不是默认 `center top`（对脸朝上的照片）。
- 缩略图测试通过（缩到 360 px 宽，标题不费力就能读）。
- 标题后面没有贴纯黑 / 纯白矩形。

任意一项失败就修，不要"先发出去以后再调"。

## 9 截图处理工具类与 13 张材质背景

参考 [`references/screenshot-treatment.md`](../references/screenshot-treatment.md)。

### 9.1 何时用 `.frame-shot`

当用户提供 app / web / 代码 / dashboard 截图时，**不要**直接丢进 `.frame-img`。比例不匹配会裁掉 UI，硬边显得 SaaS 风。用 `.frame-shot`——两个种子模板里都有，是 `.frame-img` 的兄弟类。

触发场景：

- App / Web UI 截图（带状态栏、tab bar、工具栏、窗口 chrome）。
- 代码 / 终端截图。
- Dashboard / 图表截图（每个标签都要能读）。
- IDE 截图（文字密度比构图重要）。

**摄影内容**（人、风景、产品）继续用 `.frame-img`。

### 9.2 参数矩阵（一次性选好，不要边写边改）

```
.frame-shot.r-{ratio}.corners-{sq|sm|md}.shadow-{none|soft|ed}.bg-{paper|paper-2|grid|dot|grey-1|ink}.inset-{none|sub|bal}
  └─ <img src="…">         （默认 object-fit: contain）
```

#### 比例（`r-*`，必填，按槽位选）

| 类 | 用途 |
| --- | --- |
| `r-16x10` | 默认 app / web 截图，像真窗口 |
| `r-16x9` | 横版视频 / dashboard / 宽图 |
| `r-4x3` | 经典桌面窗口、老 app |
| `r-3x2` | DSLR 风格——只有当源就是摄影类 UI mockup |
| `r-1x1` | App 图标 / 方形 widget |
| `r-3x4` | 移动竖版截图（搭配 `.device-phone`） |
| `r-21x9` | 多显示器 / 超宽 / 公众号 hero |

#### 圆角（`corners-*`，风格锁默认）

- Swiss 默认 `corners-sq`（方角），只在槽位本身带阴影或 chrome 时才用 `corners-sm`。
- Editorial 默认 `corners-sm`（6 px），想要"剪报"感时升到 `corners-md`（14 px）。
- **不要超过 14 px**，再大就读起来像 iOS 营销。

#### 阴影（`shadow-*`，风格锁默认）

- Swiss 90% 用 `shadow-none`。`shadow-soft` 只在截图浮在 `bg-grid` / `bg-dot` 上时用。`shadow-ed` 自带 1 px 描边作为阴影的一部分，只给 hero 截图。
- Editorial 在 `bg-paper-2` 上 `shadow-soft` 是温润默认。`shadow-ed` 给 hero 截图。

#### 舞台底色（`bg-*`）

| Token | Swiss 角色 | Editorial 角色 |
| --- | --- | --- |
| `bg-paper` | 默认纯色台 | 同 |
| `bg-paper-2` | n/a | 默认暖色台 |
| `bg-grey-1` | 默认纯色台 | n/a |
| `bg-grid` | 工程 / 数据 | 田野工程笔记 |
| `bg-dot` | 细微结构 | 细微结构 |
| `bg-ink` | 深色 UI 截图 | 深色 UI 截图 |

舞台底色**永远不用强调色**。截图需要强调时，加 `.t-cat` chip 或 `.kicker`，不要染舞台。

#### 内外边距（`inset-*`）

- `inset-none`：图填满框（截图本身已带窗口 chrome 时用）。
- `inset-sub`：Swiss 20 px / Editorial 24 px（默认）。
- `inset-bal`：Swiss 48 px / Editorial 56 px（截图很满，需要安静感时）。

#### 覆盖（`fit-cover`）

默认 `object-fit: contain`——这正是 `.frame-shot` 的全部意义。**只有**符合下列条件时才加 `.fit-cover`：

- 槽位是 hero，源像素是否精确不重要（比如把代码截图当背景纹理）。
- 用户明确说要把截图裁掉。

### 9.3 真实材质底（`bg-asset-*`，13 张 WebP）

仓库在 `assets/screenshot-backgrounds/` 下分两组：

```
assets/screenshot-backgrounds/
├── style-a/   (5 张，Editorial 用)
│   ├── dune.webp
│   ├── forest-ink.webp
│   ├── indigo-porcelain.webp
│   ├── kraft-paper.webp
│   └── monocle-classic.webp
└── style-b/   (4 张，Swiss 用)
    ├── ikb-dot-gradient.webp
    ├── lemon-green-dot-shadow.webp
    ├── lemon-grid.webp
    └── safety-orange-halftone.webp
```

Editorial 资产（`style-a/`）：

| 类 | 色调 | 适用 |
| --- | --- | --- |
| `bg-asset-dune` | 暖沙 | 旅行 / 户外 app 截图、生活方式产品 |
| `bg-asset-forest-ink` | 深森林绿 | Editorial 深色 UI（配 `ink-classic`） |
| `bg-asset-indigo-porcelain` | 冷瓷 | 阅读 / 写作 app、设计工具 |
| `bg-asset-kraft-paper` | 牛皮纸 | 笔记 / 日记 / 手写 app |
| `bg-asset-monocle-classic` | 米色纸 | 默认暖 hero——最杂志感 |

Swiss 资产（`style-b/`）：

| 类 | 强调色 | 只在当前 `data-accent` 一致时用 |
| --- | --- | --- |
| `bg-asset-ikb-dot` | IKB Klein Blue | `data-accent="ikb"` |
| `bg-asset-lemon-green-dot` | 柠檬绿 | `data-accent="lemon-green"` |
| `bg-asset-lemon-grid` | 柠檬黄 | `data-accent="lemon"` |
| `bg-asset-safety-orange` | Safety Orange | `data-accent="safety-orange"` |

使用规则：

- **不要混强调色**——`data-accent="ikb"` 的 deck 不能拉 `bg-asset-safety-orange` 舞台。
- 资产底已经带纹理，**不要再叠** `shadow-ed`（那 1 px 描边读起来像 SaaS 框）。用 `shadow-soft` 或 `shadow-none`。
- 一本 deck 要决定"用不用资产底"——不要在一堆纯色台里夹一张资产底，那会像样品卡。
- 资产底在 `r-16x10` 和 `r-16x9` 是 crop-safe 的。`r-3x4` 或 `r-1x1` 这种被裁得太狠的，优先用纯色 `bg-*`——纹理过度裁切会读得别扭。

**路径注意**：`.bg-asset-*` 的 CSS 用 `url("../../assets/screenshot-backgrounds/…")`，假设 deck 的 `index.html` 位于比 `assets/` 低两层的任务目录里（默认 `local-tests/<slug>/`）。如果 deck 放到别处，本地覆盖这条规则。

### 9.4 设备外壳（device chrome）

两个种子模板都自带两个包装类，套在 `.frame-shot` 外：

- `.device-browser`：32–36 px chrome bar，三个 traffic-light 圆点。
- `.device-phone`：ink 色 bezel，18–24 px 内圆角。

注意：`.device-phone` 不要叠 `corners-md`——bezel 已经把内截图圆了。

### 9.5 截图预处理

用户给完整全屏截图（iOS 1290×2796 / Android 1080×2400 / Desktop 1920×1080）时，**不要**展示状态栏 / dock / 浏览器 tab 条，除非它们就是主体。先裁后导入：

1. 裁掉 iOS / Android 状态栏（retina 顶部 47–59 px）。
2. 裁掉 home indicator / nav gesture bar（iOS 底部 34 px）。
3. Desktop：除非套了 `.device-browser`，否则裁掉页面内容以上的部分。

来不及预裁，用 `object-position: center 6%` 把可视区往下偏一点——只是兜底，不是首选。

### 9.6 两个万能配方

| 场景 | 配方 |
| --- | --- |
| Swiss 产品 demo | `.frame-shot.r-16x10.corners-sq.shadow-none.bg-grey-1.inset-bal` |
| Editorial deep-dive | `.frame-shot.r-16x10.corners-sm.shadow-soft.bg-paper-2.inset-sub` |
| Editorial hero + 真实纹理 | `.frame-shot.r-16x10.corners-sm.shadow-soft.bg-asset-monocle-classic.inset-bal` |
| Swiss hero + 品牌色舞台 | `.frame-shot.r-16x10.corners-sq.shadow-none.bg-asset-ikb-dot.inset-bal`（仅当强调色匹配时） |

对比截图（before / after）必须用**同样的参数**——单元之间不一致读起来是"不一致"，不是"对比"。

## 10 地图组件

参考 [`references/map-component.md`](../references/map-component.md)。当内容有**空间关系**（旅行路线、店铺位置、街区概览、徒步、定居前后对比）时用。"我在北京"这种单点不需要地图。

两个种子模板都自带 `.map-block` + `.map-pin` + `.map-legend`。

### 10.1 三种渲染模式（不叠加，写之前选好）

| 模式 | 用途 | 来源 |
| --- | --- | --- |
| **Mode T** | 真实路线 / 徒步 / 街区寻路——默认 | Mapbox Static Images API（需要 `MAPBOX_ACCESS_TOKEN`） |
| **Mode O** | 同上但没有 Mapbox token 时的兜底 | OSM static tile 合成（用 `staticmaps` npm 包之类服务端渲） |
| **Mode S** | 概念关系图、虚构路线、纯编辑感"地点是这样连的"插画 | 手画 SVG，`viewBox="0 0 100 100"` |

### 10.2 Mode T 地图样式白名单

只用：

- `mapbox/light-v11`
- `mapbox/dark-v11`
- `mapbox/streets-v12`（必须配合 `tone-paper`，绝不裸用）

`outdoors-v12` / `satellite-v9` 太花，与三套系统都打架。

### 10.3 色调（`tone-*`）

| Token | Editorial 行为 | Swiss 行为 |
| --- | --- | --- |
| （无） | 仅用于 SVG 示意图 | 仅用于 SVG 示意图 |
| `tone-paper` | multiply 混合到暖纸。旅行默认。 | 硬灰阶。所有瑞士默认。 |
| `tone-ink` | brightness 62%，saturation 18%。深色 deck 页。 | brightness 58%，saturation 0%。深色海报。 |

色调只影响 `> img`，不影响 SVG schematic。

### 10.4 硬规则

- **SVG / 栅格图上不放 pin 标签**。名字只放在 `.map-pin .card` 里，不用 SVG `<text>`，也不烤进地图图。
- 每板 **≤ 6 个 pin**。再多 pin card 会撞，改用 relations / index 卡列次要点。
- 每板**最多 1 个强调 pin**。多个强调色等于取消强调。
- pin 不能跟 card 重叠。先在浏览器里看——如果两张 card 在长轴方向 80 px 以内，把其中一张加 `.left` 翻边。
- **不要 live JS map**。社媒卡是静态 PNG，MapLibre 是浪费重量。

### 10.5 pin 摆位经验

`.map-pin` 用 `left:X%; top:Y%;` 以中心定位。card 默认向右展开，加 `.left` 翻左：

```html
<div class="map-pin left" style="left:78%; top:30%;">
  <div class="dot"></div><div class="line"></div>
  <div class="card"><div class="name">车公庄</div><span class="meta">START</span></div>
</div>
```

经验：

- pin 在画板左 60% → card 向右开（默认）。
- pin 在画板右 60% → card 向左开（`.left`）。
- 两个 pin 靠近 → 交替翻边，card 不堆叠。

### 10.6 SVG schematic 里的图层顺序（从底到顶）

1. `.map-water`（河、湖、公园）。
2. `.map-coast`（边界）。
3. `.map-grid`（参考网格线，可选）。
4. `.map-road`（交通线）。

Pin 在 SVG 外，作为 HTML 兄弟节点。

### 10.7 地图接入版式

| 版式 | 地图怎么放 |
| --- | --- |
| M01 split | 上半 = `.map-block r-16x9`；下半 = 解释文字 |
| M11 marginalia | 主栏 = `.map-block r-3x4`；侧栏列关系卡 |
| M14 pipeline | 某一步里塞一个小地图（`r-16x10`）显示该步位置 |
| S02 two signals | 一个信号格放地图，另一个放数据表 |
| S08 image hero | hero 图换成 `.map-block r-16x10` |

不要发明"纯地图页"——地图必须配文字说明空间关系**为什么**重要。

### 10.8 常见错误

- **贴 Google Maps 截图**——色调不对，带 UI chrome。改用 Mapbox Static / OSM 静态瓦片 / schematic。
- **真地图描成 SVG**——schematic 应该是**抽象**。如果观众光看 SVG 就能猜出城市，你描过头了。
- **pin card 太小**——`.card .name` 至少 15–16 px。溢出就砍名字，绝不缩字号。
- **每个 pin 都强调色**——强调系统失效。挑一个最重点的。

## 11 1:1 短标题推导

参考 [`references/title-shortener.md`](../references/title-shortener.md)。

### 11.1 为什么需要单独写一句

3:4 小红书封面 / 21:9 公众号封面上成立的长标题，**塞不进** 1:1 方封面。方封面需要一句不同的——更短、更直接、一个 idea 一眼击中。

| 源标题（3:4 / 21:9） | 直接塞进 1:1 | 推导出的短标题 |
| --- | --- | --- |
| 第三次进山，装备比上一次轻 3.4kg | 88 px 下溢出，跟照片打架 | 装备减重 3.4kg |
| 开源了一个 Skill，让 AI 接管你屏幕边那张便签纸 | 折 3 行，看起来像段落 | AI 接管便签纸 |
| 当代年轻人，不为了变美，只为了不丑 | 在 `.poster.square` 上折 4 行 | 不为变美，只为不丑 |
| 我把家从北京搬到大理后，第一次安静地写完了一本书 | 即使 80 px 也溢出 | 北京到大理，写完一本书 |

直接塞版本读起来像一堵墙。推导版本读起来像海报标题。

### 11.2 五步推导法

1. **找核心动词**。每个好海报标题都有一个：`接管` / `减重` / `搬到` / `写完`。丢掉修饰语、丢掉前置铺垫、丢掉形容噪音。
2. **找核心宾语**。动词作用在什么上：`便签纸` / `装备` / `家` / `书`。跳过定语（`你屏幕边那张` → `便签纸`）。
3. **压到 4–10 个汉字**。这是 88–120 px 在 1080×1080 画板上的可读带。带外要么 2 行（还行）、3+ 行（基本错），要么用 typography stunt（一个巨字 + meta，见 Big Word 模式）。
4. **丢掉英文，除非英文承担动词**。CJK + Latin 在大字号混排是 Swiss / Editorial 的技巧，要练。1:1 短标题里优先纯中文。例外：品牌名（`AI` / `Mac` / `iOS`）、无中文等价物的领域词（`PPT` / `MCP`）。
5. **只在需要消歧时加小副标**。大多数 1:1 封面不需要。如果实在要加，用 `.kicker` 或 `.t-meta` 尺寸（20–22 px mono），绝不用第二个 `.h-xl`。

### 11.3 1:1 封面的可用模式

#### A · 动词 + 宾语（单行 4–8 字）

```
装备减重 3.4kg
AI 接管便签纸
家搬到大理
眼线一笔到位
```

动词具体、宾语短时用。标题独立完成工作——不要副标。

#### B · 双句切断（逗号在中间，2 行）

```
不为变美，
只为不丑

六个停靠点，
两天走完
```

需要对比或起承转合时用。**手动**在逗号处 `<br>`，不要让 CJK 自动换行决定断行。每行 ≤ 6 字。

#### C · Big Word（一个巨字 + meta）

```html
<h1 class="h-hero" style="font-size:520px; line-height:0.86;">家</h1>
<p class="t-meta">从北京搬到大理</p>
```

当一个汉字本身就是文章的"概念锚"时，单字可以扛封面。配 1 行 mono meta。**不要试 2 字**——2 字永远比 1 字或 4+ 字难看。

#### D · 数字领头的标题

```
↓ 3.4kg
装备减重

1+1=3
共创笔记
```

数字事实本身是新闻时，让它打头。Editorial 用 `.num-mega`（200 px）配 56 px serif 副标；Swiss 用 `.num-mega`（200 px）配 22 px mono cat。

### 11.4 反模式

- **塞 21:9 标题**。克制住用同一句话的冲动。方封面要一句独立的话。
- **加"如何" / "怎样" / "为什么"开场**。问句太长不适合 1:1。改成陈述：`怎样减重装备` → `装备减重 3.4kg`。
- **三行标题**。`.poster.square` 上 draft 折 3 行就**缩文案**——不要把 `.h-hero` 缩到 152 px 以下。三行塌成段落。
- **长副标**。1:1 封面带 2 行副标读起来像传单。如果副标非写不可，你大概选错了版式——切回 `.poster.xhs` 3:4。
- **中文内容配纯英文标题**。读起来像 stock 模板。只在英文本身就是 headline 时混排（比如品牌发布）。

### 11.5 `.poster.square` 上的字号（1080×1080）

| 风格 | 类 | 默认尺寸 | 用途 |
| --- | --- | --- | --- |
| Editorial | `.h-display` | 110 px | Pattern A 或 B，1–2 行 |
| Editorial | `.h-xl` | 78 px | 副标或次要 headline |
| Swiss | `.h-hero` | 200 px | Pattern A 或 B，1–2 行 |
| Swiss | `.h-statement` | 160 px | 同 `.h-hero`，更收 |
| 共有 | `.num-mega` | 200 px | Pattern D 的领头大数字 |

Swiss 方封面上单行 ≤ 4 个汉字时，`.h-hero` 可以推到 240 px 不溢出。

### 11.6 跨平台搭配

同一内容同时出小红书 carousel + 公众号封面对 + 旅书单图：

| 画板 | 标题来源 | 长度带 |
| --- | --- | --- |
| XHS p1 封面（3:4） | 自己写的长标题（12–30 字） | 1–2 行，每行 ≤ 9 字 |
| WeChat 21:9 主 | 长标题或其 80% | 1 行 ≤ 14 字 |
| WeChat 1:1 方 | 按本节五步推导（4–10 字） | 1–2 行，每行 ≤ 6 字 |
| 旅书单图（3:4） | 与 XHS p1 同，或压到 8–12 字 | 1–2 行 |

1:1 短标题是这一族里**最短**的。如果已经压不下去还不丢意思——内容大概需要换 framing，去跟用户聊。

### 11.7 工作流接入

当用户任务包含"公众号封面" / "WeChat cover"时：

1. 先写 21:9 长标题。
2. 用本节五步推导 1:1 短标题。
3. 两条都写进计划笔记再渲。
4. 在同一个 HTML 里渲两份，外加 `.pair-preview` 区把两份并排放。

如果用户只给一句、又要封面对，自己推导短的、并在响应里**显式提示**用户短标题怎么来的（不要默默换文案——用户需要确认缩短后意思对）。

## 12 种子模板结构解剖

两个种子模板都在 `assets/` 下：

| 模板 | 行数 | 关键切换属性 | 适用版式 |
| --- | --- | --- | --- |
| `assets/template-editorial-card.html` | 838 | `<html data-theme="…">` | M01–M16 |
| `assets/template-swiss-card.html` | 943 | `<html data-accent="…">` | S01–S12 |

文档未明确说明两个模板的具体生成日期，但 `assets/template-editorial-card.html:194-198` 标注的字号恢复注释显示 Editorial 默认值是"Restored 2026-05-27"。

### 12.1 共同的画板类

两个模板都内建三种画板，写在 `.poster` 之后：

| 类 | 像素 | 类名组合 |
| --- | --- | --- |
| 3:4 小红书 | 1080 × 1440 | `.poster.xhs` |
| 1:1 方封面 | 1080 × 1080 | `.poster.square` |
| 21:9 主封面 | 2100 × 900 | `.poster.wide` |

对应使用场景：

```html
<section class="poster xhs"    id="xhs-01">…</section>
<section class="poster square" id="wechat-1x1">…</section>
<section class="poster wide"   id="wechat-21x9">…</section>
```

公众号封面要再加一个 `<section class="pair-preview">` 把 21:9 + 1:1 并排。`.pair-preview` 在两个模板里都内建，固定 `2400px` 宽、`1180px` 高，使用同一种网格布局。

### 12.2 Editorial 模板结构（`assets/template-editorial-card.html`）

#### 12.2.1 根元素 / 字体加载

```html
<html lang="zh-CN" data-theme="ink-classic">
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Noto+Serif+SC:wght@400;500;700;900&family=Noto+Sans+SC:wght@300;400;500;700&family=Playfair+Display:ital,wght@0,400;0,700;1,400&family=Inter:wght@300;400;500;700&family=IBM+Plex+Mono:wght@400;500&display=swap">
```

字体：Noto Serif SC（400/500/700/900）、Noto Sans SC（300/400/500/700）、Playfair Display（400/400 italic/700）、Inter（300/400/500/700）、IBM Plex Mono（400/500）。

#### 12.2.2 主题 token 块

每个 Editorial 主题作为独立 `[data-theme="…"]` 块写在 `:root` 之后。块内声明：`--paper` / `--paper-2` / `--ink` / `--muted` / `--line` / `--accent` / `--accent-soft`，外加 `--ink-rgb` / `--paper-rgb` / `--accent-rgb` 三个逗号分隔的 0–255 字符串供 WebGL 助手读取。

#### 12.2.3 内置组件类

`.kicker` / `.h-display` / `.h-xl` / `.h-md` / `.h-sub` / `.pullquote` / `.lead` / `.body` / `.meta` / `.label`（字号阶梯见 [5.2](#52-字号阶梯editorial3-4-默认)）；`.frame-img` 与 `.frame-shot` 比例类；`.device-browser` / `.device-phone`；`.map-block` / `.map-pin` / `.map-legend`；`.callout` / `.ledger` / `.marginalia` / `.pipeline-v` / `.beforeafter` / `.issue-row` / `.issue-strip` / `.rule` / `.rule-accent` / `.stack` / `.row` / `.gap-1` … `.gap-5` / `.col-2` / `.col-3` / `.col-2-7-5` / `.col-2-8-4` / `.pair-preview`。

#### 12.2.4 背景层与 Midnight Ink 覆盖

`.mag-bg` / `.grain` / `.paper-wash` 三个氛围层叠在 `.poster` 内、`z-index: 0–2`、`.content` 在 `z-index: 2`（与 `.mag-bg` 不冲突，因为 `.content` 在 2、`.mag-bg` 在 0，`.grain` 与 `.paper-wash` 在 1）。`[data-theme="midnight-ink"] .grain` / `.paper-wash` / `.frame-img` 三段反色覆盖已写死，切换 `data-theme` 即生效。

#### 12.2.5 `<!-- POSTERS_HERE -->` 用法

模板里只有一段占位（在 `<main class="sheet">` 内部），被包成一条 HTML 注释。直接 `<section>` 替换注释，把真实海报内容贴进去，**不要在 `<main>` 外加东西**。每个 `<section class="poster">` 内放一个 Layout Recipe（M01–M16，详见 [04-内容策划与版式骨架](./04-内容策划与版式骨架.md)）。

#### 12.2.6 WebGL 脚本挂载

模板底部已经写好挂载逻辑：等 `load` 事件后读 CSS 变量 `--ink-rgb` / `--paper-rgb` / `--accent-rgb`，对每个 `canvas.mag-bg` 调用 `MagazineBg.mount(canvas, { ink, paper, accent, strength: 0.32, frozenTime: 12.5 })`。如果要重挂或换参数，直接改这段。

### 12.3 Swiss 模板结构（`assets/template-swiss-card.html`）

#### 12.3.1 根元素 / 字体加载

```html
<html lang="zh-CN" data-accent="ikb">
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Inter:wght@200;300;400;500;600;700&family=Noto+Sans+SC:wght@200;300;400;500;600;700&family=IBM+Plex+Mono:wght@400;500;600&display=swap">
<script src="https://unpkg.com/lucide@latest/dist/umd/lucide.min.js"></script>
```

字体：Inter（200–700）、Noto Sans SC（200–700）、IBM Plex Mono（400–500/600）。**没有衬线字体**。Lucide 通过 unpkg CDN 加载。

#### 12.3.2 强调色 token 块

`[data-accent="ikb" | "lemon-yellow" | "lemon-green" | "safety-orange"]` 各自声明：`--paper` / `--ink` / `--grey-1` / `--grey-2` / `--grey-3` / `--accent` / `--accent-on`。所有 4 套共用同一组 `--paper` / `--ink` / `--grey-*`，只换 `--accent` / `--accent-on`。

#### 12.3.3 间距 token

11 个 `--sp-3` … `--sp-13` 标量（8/12/16/24/32/40/48/64/80/96/160 px）。所有 gap / padding 通过 `--sp-*` 走。

#### 12.3.4 内置组件类

`.h-hero` / `.h-statement` / `.h-xl` / `.h-md` / `.lead` / `.body` / `.t-cat` / `.t-meta` / `.num-mega` / `.num-xl` / `.mono`（字号阶梯见 [5.3](#53-字号阶梯swiss3-4-默认)）；`.frame-img` 与 `.frame-shot` 比例类；`.device-browser` / `.device-phone`；`.map-block` / `.map-pin` / `.map-legend`；`.card-ink` / `.card-accent` / `.card-fill` / `.card-outlined`；`.image-hero` / `.kpi-tower-row` / `.h-bar-chart` / `.stacked-ledger` / `.matrix-fill` / `.hero-stat-bottom`；`.chrome-min` / `.hr-hairline` / `.hr-accent`；`.stack` / `.row` / `.gap-3` … `.gap-10` / `.grid-12` / `.grid-2-9` / `.grid-3` / `.grid-4` / `.span-N` / `.center` / `.right` / `.uppercase`；`.pair-preview`。

#### 12.3.5 装饰层（默认关闭）

`.dot-mat` / `.ring-mat` / `.cross-mat` 三个 0.06–0.08 不透明度的点 / 环 / 十字纹理，可选叠加。Swiss 模板不像 Editorial 默认开氛围层——海报默认就是纯色纸。

#### 12.3.6 卡片填充互斥

`.card-ink` / `.card-accent` / `.card-fill` / `.card-outlined` 四类互斥，在同一节点上不组合。多卡网格统一用一个类，最多一个 `.card-accent` 高亮。来源同 [5.12](#512-swiss-卡片填充类互斥)。

#### 12.3.7 `<!-- POSTERS_HERE -->` 用法

与 Editorial 一致：在 `<main class="sheet">` 内直接 `<section>` 替换。每个 `<section class="poster">` 内放一个 Layout Recipe（S01–S12）。

#### 12.3.8 Lucide 初始化

模板底部：

```html
<script>
  if (window.lucide && typeof window.lucide.createIcons === 'function') {
    window.lucide.createIcons();
  }
</script>
```

仅在加载完成时跑一次。**加载后注入图标需要再手动调一次**。

### 12.4 禁止混用三套类系统

种子模板里的类分三套，各自成体系。**跨用会塌版**，因为 token 命名空间不重合（Editorial 的 `--serif-zh` 在 Swiss 模板里没声明；Swiss 的 `--sp-*` / `--grey-*` 在 Editorial 模板里没声明；Warm Gold 的金工具类只在暖金种子声明）。下列任意一条都视为混用：

- 在 Swiss 模板里用 `.pullquote` / `.marginalia` / `.callout` / `.ledger`（Editorial 专属类）。
- 在 Editorial 模板里用 `.h-hero` / `.h-statement` / `.num-mega` / `.card-fill` / `.kpi-tower-row`（Swiss 专属类）。
- 在 Editorial 模板里 `<html data-accent="…">` 或在 Swiss 模板里 `<html data-theme="…">`（属性互斥）。
- 把 Editorial 主题 token 套到 Swiss 模板或反过来。
- 把 `assets/magazine-bg-webgl.js` 挂到 Swiss 模板的画板上（Swiss 默认无氛围层；混用会破坏硬规则）。

判定方法：如果任何 CSS 变量解析为 `initial` / 未定义，那就是混用了。

### 12.5 共同硬规则速查

整理自 [`components.md:274-285`](../references/components.md)：

1. 一本 deck 只选一种视觉模式，**不混** Editorial 与 Swiss。
2. 一本 deck 只选一种主题 / 强调色，**不混**跨系统色票。
3. 任何位置**不用 emoji**，用 Lucide 或克制排版。
4. 交付稿里**没有假数据 / 假百分比 / Lorem**。
5. Swiss 里**不用** `border-radius` / `box-shadow` / `linear-gradient`。
6. Editorial 里**不许**纯色单层背景——hero / 引语 / 稀疏页必须有纸纹 + 可选 WebGL 氛围。
7. 每个 `.poster` 必须有稳定导出尺寸。poster 内容里**不用** `vw` / `vh`。
8. 每张图必须包在 `.frame-img` 里，并带标准比例类。
9. 多卡网格用同一卡片类，最多一个 `.card-accent`。
10. 遵守字号阶梯和最小尺寸。**先砍文案再缩字号**。
