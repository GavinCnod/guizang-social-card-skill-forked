# 工具链与脚本

本文档说明本 Skill 在 Agent 环境里"靠什么工具跑起来"：从单文件 HTML 到 PNG、到 Live Photo `.pvt` 包需要哪些运行时，仓库自带的校验脚本、文档自检脚本和 npm 入口各自做什么，agent 元数据如何被识别，以及 Skill 根目录与任务目录的边界约定。其他主题——设计规则细节、Live Photo 视频脚本调用、种子模板类名——见对应的姊妹文档。

## 1. 工具链全景

一次完整任务（小红书图文 / 公众号封面对 / Live Photo 动态卡）的流水线大致如下，按"是否随仓库分发"标注：

| 阶段 | 工具 | 用途 | 是否必需 |
|------|------|------|----------|
| 编辑 HTML / CSS | 任意文本编辑器 / Agent | 拼装 `.poster` 节点、版式骨架、种子模板替换 | 必需 |
| 浏览器引擎 | Chromium（由 Playwright 自带） | 真实渲染页面供截图与 DOM 测量 | 必需 |
| 截图 | Playwright `page.screenshot` / `elementHandle.screenshot` | 把每个 `.poster` 节点截成 PNG | 必需 |
| 版式校验 | `validate-social-deck.mjs` | 真实 DOM 测量，跑 R1-R11 规则 | 可选（默认不自动跑，见 §2.6） |
| 文档自检 | `scripts/check-skill-docs.mjs` | 校验仓库文本约定是否被破坏 | CI / 改文档时跑 |
| 抽帧 / 预览 | `scripts/make-video-contact-sheet.py`（基于 `ffmpeg` / `ffprobe`） | 给长视频做 contact sheet，用于 Live Photo 选段 | 仅 Live Photo 分支 |
| Live Photo 打包 | `scripts/package-live-photo.py`（基于 `makelive==0.7.0`） | 把 JPG + MOV 打成一个 `.pvt` 包 | 仅 Live Photo 分支 |
| Apple 元数据写入 | `scripts/add-livephoto-maker-note.swift` + `scripts/add-livephoto-mov-metadata.swift` | 给 JPG 写 MakerNote，给 MOV 写 QuickTime content identifier / still-image-time | 仅 Live Photo 分支，macOS + Swift 可用时 |
| 视频元数据诊断 | `ffprobe` / `sips` | 查看产物尺寸、时长 | 可选 |

> 关键事实：`validate-social-deck.mjs:48-50` 启动 Chromium 时显式传入 `--use-angle=swiftshader --enable-unsafe-swiftshader`，保证无 GPU 容器里也能跑软件光栅化。

## 2. `validate-social-deck.mjs` 详解

### 2.1 定位

这是仓库根目录自带的一份 **Playwright 真实 DOM 测量** 校验脚本，不是静态文本/正则扫描。它启动 Chromium，把目标 HTML 当作 `file://` 加载，等字体与资源就绪后，对每个 `<section class="poster …">` 节点逐一跑 R1-R11 规则并产出报告。

### 2.2 命令行用法

```bash
# 校验一个任务目录（脚本会读取其下的 index.html）
node validate-social-deck.mjs path/to/task-dir

# 直接校验一个 HTML 文件
node validate-social-deck.mjs path/to/index.html

# 显式指定风格模式（覆盖自动识别）
node validate-social-deck.mjs path/to/task-dir --style=swiss
node validate-social-deck.mjs path/to/task-dir --style=editorial
node validate-social-deck.mjs path/to/task-dir --style=warmgold
```

参数解析在 `validate-social-deck.mjs:26-32`：第一个非 `--style=` 前缀的位置参数是 target；其余位置参数忽略。target 不存在时退出码 `2`（参数错误），见 `validate-social-deck.mjs:34-45`。

### 2.3 输出格式

`validate-social-deck.mjs:512-545` 拼出报告文本，逐 section 列出 `[PASS] / [FAIL] / [WARN]` 三种标签，并在末尾附一行图例。结构示意：

```text
==== validate-social-deck ====
target:   local-tests/social-card-hiking-outfit/index.html
style:    swiss
sections: 6  ·  2 clean  ·  3 fails  ·  1 warns
rules:    R1=2  R2=1  R8=1

[FAIL]  xhs-01 · hiking-outfit-cover · xhs
  FAIL · R1  overflow 24px (scrollH 1464 > clientH 1440)
         fix: only 24px over: nudge content up or tighten one gap/padding by 20-40px; do not delete content
  WARN · R4  body "咖啡因对睡眠的影响" at 20px < 22px floor
         fix: cut copy instead of shrinking type (components.md Minimum Readable Sizes)

Legend: R1 overflow · R2 footer collision · R3 swiss bold display · R4 min font · R5 4-band density · R6 h-xl cap · R7 figure margin drift · R8 visual bounds · R9 title gap
Exit code 1 only on FAIL. Warnings are advisory.
```

每条 FAIL/WARN 下方只打印一次该规则的修复建议（用 `fixCache` 去重，见 `validate-social-deck.mjs:523-538`）。

### 2.4 退出码

| 退出码 | 触发条件 |
|--------|----------|
| `0` | 全部 section 既无 FAIL 也无 WARN，或仅有 WARN |
| `1` | 至少一个 FAIL（`process.exit(totalFail > 0 ? 1 : 0)`，见 `validate-social-deck.mjs:546`） |
| `2` | 参数错误：未传 target，或 HTML 文件不存在（见 `validate-social-deck.mjs:34-44`） |

> WARN 是建议性的：脚本明确写出 "Exit code 1 only on FAIL. Warnings are advisory."（`validate-social-deck.mjs:543`）。

### 2.5 风格模式识别

`validate-social-deck.mjs:59-72` 用以下启发式判断当前页是 `swiss` 还是 `editorial`：

1. `<html data-theme>` 存在 → `editorial`；
2. `<html data-accent>` 存在 → `swiss`；
3. 否则扫描 `.h-display / .h-xl / .h-hero / .pullquote / .h-statement`，任一计算样式的 `font-family` 命中 `noto serif / playfair / source serif / songti / stsong / simsun / serif sc / kinfolk / merriweather`（按 token 匹配，避免误中通用名 `sans-serif`）→ `editorial`；
4. 兜底 → `swiss`。

`--style=` 参数可覆盖自动识别。

### 2.6 R1-R11 规则总表

阈值直接来自代码中的常量，未在代码里写出的字段标"代码中未定义"。

| 编号 | 名称 | 检查内容 | 阈值 | 触发后果 |
|------|------|----------|------|----------|
| R1 | Overflow（溢出） | `scrollHeight - clientHeight`：`validate-social-deck.mjs:129` | `> 4px` 才 FAIL | FAIL，附 `overflowFix()` 给出的修复阶梯（见 §2.7） |
| R2 | Footer Collision（页脚碰撞） | `.foot / .issue-strip / .magazine-foot` 是 `position:absolute`，且其上方文本或媒体节点的 bbox 下边沿超过 foot 顶边 | 重叠 `> 6px` 才 FAIL：`validate-social-deck.mjs:268` | FAIL，建议改用 flex `margin-top:auto` |
| R3 | Swiss Bold Display（Swiss 大字违规） | 仅 `style === "swiss"` 时启用；`.h-xl / .h-hero / .h-statement / .h-display / .num-mega / .num-xl` 中字号 `≥ 72px` 且 `font-weight ≥ 600` | 命中即 FAIL：`validate-social-deck.mjs` | FAIL，要求移除 inline 字重，沿用 typed class 默认 |
| R4 | Min Readable Font（最小可读字号） | `.body / p.body / .lead / .kicker / .cap / .caption / .swiss-img-caption / .h-sub / .meta / .label / .mono / .matrix-fill .cell-title / .brief-card .title / .char-grid .name / .stat-card .lbl / .ledger .sub / .num .sub` 叶子文本 | `MIN_FONT`（见下） | WARN（非 FAIL），建议删文案而不是缩字 |
| R5 | 4-Band Density（四横带密度） | 仅 `board === "xhs"` 时启用：把 1440px 切成 4 个等高横带，按行扫描每个元素占据的像素行数，统计每带填充率 | 平均填充 `< 0.745` WARN；相邻两带都 `< 0.15` 也 WARN：`validate-social-deck.mjs:391-400` | WARN，建议扩写或换 recipe |
| R6 | H-XL Hard Cap（主标题行数上限） | `.h-xl / .h-hero / .h-display / .h-statement` 的渲染行数 | `HXL_CAPS` 按画板：`xhs` `maxLines:2 / maxChars:8`；`square` `maxLines:2 / maxChars:7`；`wide` `maxLines:1 / maxChars:14`（`validate-social-deck.mjs:88-92`） | 行数超 `maxLines` 时 WARN；最长词超 `maxChars + 2` 仅 soft warn（不打印） |
| R7 | Figure Margin Drift（`<figure>` 边距漂移） | `figure` 元素的 `margin-left / margin-right` | 任一 `≥ 16px` 即 WARN：`validate-social-deck.mjs:336` | WARN，建议在 seed CSS 中重置 `.poster figure { margin: 0; }` |
| R8 | Visual Bounds（视觉边界） | 真实可见元素（文本 / 媒体 / 1px 规则 / ≥1600px² 的填色或描边块）的 bbox 上下边沿相对 `.poster` 顶/底的位置 | `bottomOverflow > 4px` → FAIL；`topOverflow > 4px` → FAIL；`bottomGap > bottomGapLimit && activeRatio < 0.78` → WARN；`bottomGapLimit` 为 `wide:130 / square:160 / xhs:190`（`validate-social-deck.mjs:223`） | FAIL/WARN，按情况给溢出或留白修正建议 |
| R9 | Title Gap（标题贴靠） | `.h-xl / .h-hero / .h-display / .h-statement / .h-md / .row-title / .step-title` 与下一个有意义元素之间的最小间距 | `.h-md / .row-title / .step-title` 至少 `16px`；其它画板 `wide:24px / 其它:28px`（`validate-social-deck.mjs:463`） | WARN，建议先加间距再考虑删文案或改版式 |
| R10 | Warm Gold Gold Area（金铺底过量） | 仅 `style === "warmgold"`；金渐变可见面积 `≥ 60%` 画布（跳过 `background-clip:text`） | 命中即 WARN | WARN，收缩金渐变到发丝线 / 按钮 / 局部签名 |
| R11 | Warm Gold Shadow（阴影色纪律） | 仅 `style === "warmgold"`；出现纯 `#000` / `rgba(0,0,0,…)` 阴影 | 命中即 WARN | WARN，改 `rgba(122,74,0,…)` 或 `rgba(17,9,4,…)` |

`MIN_FONT` 阈值表（`validate-social-deck.mjs:79-86`）：

| 角色 | 最低 px |
|------|---------|
| `body`（`.body / p.body`） | 22 |
| `lead`（`.lead`） | 26 |
| `caption`（`.kicker / .cap / .caption / .swiss-img-caption / .h-sub`） | 18 |
| `meta`（`.meta / .label / .mono`） | 18 |
| `cellTitle`（矩阵 / 简卡 / 字格名字） | 20 |
| `numAnnotation`（统计卡标签 / 账本副标题 / 数字注释） | 20 |

### 2.7 溢出修正阶梯（R1 / R8 共用）

`overflowFix(px)` 函数（`validate-social-deck.mjs:96-108`）按溢出像素分四档给出不同修复强度，避免误删文案：

| 溢出区间 | 修复建议 |
|----------|----------|
| `≤ 40px` | 微调单个 gap / padding 20-40px；不要删内容 |
| `40 < px ≤ 90` | 局部压缩 gap / padding 并降低一个块的高度；避免切文案 |
| `90 < px ≤ 160` | 适度缩短主标题或压缩一段正文，再考虑删内容 |
| `> 160px` | 切换到更高容量的 recipe，或主动删/合并内容 |

### 2.8 规则之间的关联

- **R1 ↔ R8 平衡**：R1 改完常常会让 R8 出现"底部空白过多"的 WARN；`overflowFix()` 注释强调 "avoid over-tightening after an overflow fix"（`validate-social-deck.mjs:228`）。
- **R3 与主题色互锁**：R3 只在 `style === "swiss"` 时启用；editorial / warmgold 大字可以粗，因为三套美学规则不同。R10/R11 只对 warmgold 启用。
- **R5 限定 3:4**：R5 只对 `board === "xhs"` 启用（`validate-social-deck.mjs:353`），其它画板没有 4 横带密度检查。
- **R9 区分主标题与子标题**：local headings（`.h-md / .row-title / .step-title`）的下沿间距门槛 `16px` 低于主标题的 `24-28px`（`validate-social-deck.mjs`）。
- **R10/R11 只对 Warm Gold**：金面积与阴影色规则不碰 Editorial/Swiss；探测顺序 `data-system` → `data-theme` → `data-accent` → 字体回退。

### 2.9 何时跑

`SKILL.md` 第 7 步明确"默认不自动跑" validator（`SKILL.md:297`）：

1. 先把渲染好的 PNG 内联展示给用户；
2. 问一句"先你自己看，还是我先自动核查一遍？"；
3. 用户说"我先看"时直接停；用户说"你查吧"才跑 `node validate-social-deck.mjs <task-dir>`；
4. 跑出 FAIL 必须修；WARN 仅作为提示。

不要默默先跑 validator —— 每次数十秒到一分钟，且用户经常能比脚本更快看出问题（`SKILL.md:304`）。

### 2.10 已知的盲区

代码注释里自陈的限制（`validate-social-deck.mjs`）：

- R8 的"有意义元素"集合排除了 `<main>`、`<section>` 自身的容器 bbox，以及覆盖 `≥ 85%` 画板面积的 `position:absolute` 背景层（`validate-social-deck.mjs:155-156`）。
- R2 跳过 `position:absolute` 且覆盖 `≥ 95%` 画板面积的"满铺背景"（`validate-social-deck.mjs:257-258`）。
- R4 / R9 都要求叶子节点；含子元素的容器即使带 `.lead` 等类名也不被计入。
- 地图 pin 内部的 `.card` 装饰字号会跳过 R4 检查（`validate-social-deck.mjs:307`）。

## 3. `scripts/check-skill-docs.mjs` 详解

### 3.1 定位

文档自检脚本。它不做版式校验，而是用 `mustInclude` / `mustNotMatch` 两个 helper 检查 `SKILL.md`、`references/*.md`、`PRODUCT.md`、`HANDOFF.md` 是否仍包含约定的关键句。

### 3.2 命令

```bash
npm run test:docs
# 等价于
node scripts/check-skill-docs.mjs
```

### 3.3 覆盖的检查（按文件分组）

| 文件 | 检查类型 | 关键句（节选） | 数量 |
|------|----------|----------------|------|
| `SKILL.md` | mustInclude | "Generated work must live in a task folder, not in the skill root." | 9 处 |
| `SKILL.md` | mustNotMatch | `/Create a task folder in the current workspace/`（防止回退到根目录指令） | 1 处 |
| `references/production-workflow.md` | mustInclude | "Create a task folder under `local-tests/` by default"、"Do not create generated task folders …" | 2 处 |
| `references/live-photo-production.md` | mustInclude | "## Live Photo Information Budget"、"## Triple Live Photo Collage"、"## Material-First Puzzle Layouts"、"## Long Video Intake" 等 | 9 处 |
| `references/category-cookbook.md` | mustInclude | "## Live Photo Scene Library"、"This is not a fixed template list." | 2 处 |
| `PRODUCT.md` | mustInclude | "## 10. Live Photo 复盘（2026-07-01）"、"把内部制作要求写成观众可见文案" | 2 处 |
| `HANDOFF.md` | mustInclude | "### v0.15 · 2026-07-01"、"### v0.16 · 2026-07-22"、"不要把制作要求当成观众可见内容" | 3 处 |

合计 27 条断言（与代码 `checks.length` 一致，见 `scripts/check-skill-docs.mjs:188`）。任一断言失败：脚本打印 `FAIL` 行 + 详情，`process.exit(1)`（`scripts/check-skill-docs.mjs:183-186`）。全通过：打印 `N skill doc checks passed.`，退出码 `0`（实测输出 `27 skill doc checks passed.`）。

### 3.4 何时跑

- 修改 `SKILL.md` / `references/` / `PRODUCT.md` / `HANDOFF.md` 后跑一遍，确保关键守则没被悄悄删掉。
- CI 或发版前作为 smoke test。
- 提交 PR 之前的"最低限度自检"。

## 5. `scripts/` 目录一览

四个文件 + 一个 Python 助手，覆盖 Live Photo 视频管线与文档自检：

| 文件 | 语言 | 用途 | 典型调用 | 归属分支 |
|------|------|------|----------|----------|
| `scripts/check-skill-docs.mjs` | Node（ESM） | 文档自检 | `npm run test:docs` | 仓库元数据 / CI |
| `scripts/make-video-contact-sheet.py` | Python 3 | 用 `ffmpeg` 给视频抽帧拼成 contact sheet（Live Photo 选段） | `python scripts/make-video-contact-sheet.py input.mp4 sheet.jpg --frames 12 --cols 4` | Live Photo 长视频诊断 |
| `scripts/package-live-photo.py` | Python 3（依赖 `makelive==0.7.0`） | 把 JPG + MOV 打成一个 `.pvt` 包（AirDrop 给 iPhone 后可发布为 Live Photo） | `uvx --from 'makelive==0.7.0' python scripts/package-live-photo.py IMG.JPG IMG.MOV` | Live Photo 打包 |
| `scripts/add-livephoto-maker-note.swift` | Swift（macOS） | 给 JPG 写入 Apple `kCGImagePropertyMakerAppleDictionary` 第 17 项（17 = content identifier），让 iOS 把图识别为 Live Photo 静帧 | `swift add-livephoto-maker-note.swift input.jpg output.jpg <asset-id>` | Live Photo 元数据 |
| `scripts/add-livephoto-mov-metadata.swift` | Swift（macOS） | 用 `AVFoundation` 重写 MOV，写入 `com.apple.quicktime.content.identifier` 和 `com.apple.quicktime.still-image-time`，让 iOS 把视频识别为 Live Photo 动态段 | `swift add-livephoto-mov-metadata.swift input.mov output.mov <asset-id>` | Live Photo 元数据 |

> `package-live-photo.py` 注释明确建议通过 `uvx` 运行并把 cache 写到 `/private/tmp/`（`scripts/package-live-photo.py:6-9`），因为 `makelive` 不一定装在系统 Python 环境里。
>
> 两个 swift 脚本成对出现：先生成一个 UUID 作为 asset identifier，分别写入 JPG 和 MOV，iOS 才能把它们配成一对 Live Photo（`add-livephoto-mov-metadata.swift:5-8`、`add-livephoto-maker-note.swift:5-8`）。

## 7. 仓库边界与产物放置规则

### 7.1 `.gitignore` 拦了什么

`/local-tests/`、`/outputs/`、`/social-card-*/`、`/livephoto-*/`、`/wechat-*/`、`/output/`、根目录散落的 `*.png / *.jpg / *.jpeg / *.mov / *.mp4`、`.pvt/`、`node_modules/`、`py-libs/`、`.DS_Store`、`*.log`、`.vscode/`、`.idea/` 等。

根目录级别的 `/social-card-*/` 等通配项是双保险：即使有 Agent 误把任务产物写到根目录，至少 git 不会把这些散件收进来。

### 7.2 为什么禁止 Skill 根目录放产物

- Skill 根目录应该保持"可安装、可维护"——`SKILL.md / references / assets / agents / validate` 加上授权和项目级文档（`AGENT.md:7-23`）。
- 一旦根目录堆满 `social-card-foo/`、`livephoto-bar/`、散落的 PNG / MOV / `.pvt`，后续更新、克隆、压缩都会失控。
- `.gitignore` 拦得住 git，但拦不住本地误删、被打成 release zip 一起带走。

### 7.3 推荐任务目录结构

`AGENT.md` 第 27-48 行规定（与 `references/production-workflow.md` 的 Recommended Folder Shape 一致）：

```text
local-tests/<case-name>/
  index.html        # 必填：单文件 HTML，包含一个或多个 <section class="poster …">
  render.cjs        # 或 render.mjs：Playwright 渲染脚本
  render.mjs
  assets/           # 下载 / 临时使用的图片、截图、素材
  output/           # 渲染产物 PNG / JPG / MOV / WebP / .pvt
  SOURCES.md        # 可选：图源清单（用户图 / AI 生图 / 网络取图）
```

原则：

- HTML 试跑 → `local-tests/<case-name>/`；
- 渲染产物 → `local-tests/<case-name>/output/`；
- 临时素材 → `local-tests/<case-name>/assets/`；
- 一次性调试脚本放在对应 case 目录里；只有"通用校验 / Skill 本体需要"的脚本才放根目录或 `scripts/`。

`local-tests/` 已在 `.gitignore` 中忽略，是默认的本地测试和生成产物落地点（`AGENT.md:58`）。

### 7.4 提升为正式示例的路径

如果想把某个测试案例升级为正式示例：

1. 先明确它属于"项目文档"、"参考资料"还是"发布资产"；
2. 再移动到合适位置（`assets/` / `references/` / `examples/`）；
3. 不要默认留在根目录（`AGENT.md:55-56`）。

## 8. 常见故障排查

只写代码或文档里能推出的情况：

### 8.1 缺依赖

现象：`node validate-social-deck.mjs …` 报 `Cannot find module 'playwright'`。

处理：`npm install`，然后 `npx playwright install` 拉 Chromium。`package.json:13-15` 与 `package-lock.json:28-44` 是依赖来源。

### 8.2 渲染尺寸不对

- `.poster.xhs` 期望 `1080×1440`、`.poster.wide` `2100×900`、`.poster.square` `1080×1080`（`references/production-workflow.md:42-62`）。脚本的 board 推断基于 class 与宽高比（`validate-social-deck.mjs:113-122`）：3:4 → xhs，1:1 → square，21:9 → wide。
- 脚本启动时使用 viewport `1400×1700`、`deviceScaleFactor: 1`（`validate-social-deck.mjs:52-54`）。如果页面把 `.poster` 写到了 viewport 外或 absolute 定位失败，board 会变成 `unknown`，R5 / R6 自动跳过。

### 8.3 校验 FAIL 的处理顺序

按修复强度由轻到重（与 `overflowFix()` 阶梯一致）：

1. **R1 / R8 溢出 ≤ 40px**：先收单个 gap / padding 20-40px，不要动文案。
2. **40-90px**：局部压缩 gap / padding，降低一个块的高度，避免切文案。
3. **90-160px**：缩短主标题或压缩一段正文；先考虑 `SKILL.md:324` 的 `.h-xl` 行数 cap。
4. **> 160px**：换更高容量的 recipe（如 Swiss `S01/S05` cover），或主动合并/删除内容。
5. 修完一次溢出后再看 R8 是否变成"底部空白过多"的 WARN（`validate-social-deck.mjs:228`），避免过度收紧。
6. R2 FAIL 时把 `.foot` 从 `position:absolute` 改成 flex 容器里的 `margin-top:auto`（`validate-social-deck.mjs:271`）。
7. R3 FAIL 时把 `.h-xl / .h-hero / .h-statement` 上的 inline `font-weight` 删掉，让 typed class 默认 `200-300` 字重生效（`validate-social-deck.mjs:291`）。
8. R4 WARN 不要靠缩小字号过关——脚本建议"cut copy instead of shrinking type"（`validate-social-deck.mjs:326`）。

### 8.4 默认渲染产物没出

- 校验脚本只看 HTML、不出图。真正的 HTML → PNG 渲染依赖每个任务目录自己的 `render.cjs / render.mjs`，模式见 `references/production-workflow.md:88-115`。
- WebGL / 程序化 canvas 背景需要渲染前 `wait 500-900ms` 让画布稳定（`references/production-workflow.md:97-99`）。

### 8.5 Live Photo `.pvt` 报错

- `package-live-photo.py` 要求 `JPG` 与 `MOV` 都存在（`scripts/package-live-photo.py:27-30`）。
- iOS 必须同时看到 MakerNote 和 QuickTime content identifier，所以两个 swift 脚本要成对跑，且传入同一个 asset-id。
- macOS 上才能用 Swift 脚本；非 macOS 平台跳过元数据写入会导致 iPhone 无法识别为 Live Photo。
