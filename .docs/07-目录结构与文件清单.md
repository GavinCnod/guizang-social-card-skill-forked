## 三、`references/` 逐份说明

`SKILL.md` 的 Required References 段规定"按需读取"，触发条件与内容如下。

### 3.1 `style-system.md`（261 行）

章节：Shared Rules / Style ↔ content type are decoupled / Mode A：Editorial Magazine × E-ink / Mode B：Swiss International / Image Rules / Bad Smells / **Style Identity Test** / Anti-Patterns From Real Demos。

- 回答"三套视觉系统的硬规则是什么、怎么判断一篇内容塌出了风格"。
- 含 Editorial 的 typography stance（"越大越细"/ serif 正文 / 宽字距，反例是 700-900 字重 + sans + 负字距的"信息图横幅塌方"）与 Anti-Pattern D（封面照片裸跑无蒙版）。
- 交付 Editorial 海报前要跑里面的 Identity Test。

### 3.2 `theme-presets.md`（364 行）

章节：Editorial Magazine × E-ink Palettes / Swiss International Palettes。

- 16 套主题的完整 CSS token。
- Editorial 5 套浅色 + Midnight Ink 暗色（含"必随覆盖"代码：颗粒层、纸洗层、图框底色的联动改动），并写明"暗色 Editorial 只有这一套，不要自造第二套"。
- 不在此文件里的颜色不许自造。

### 3.3 `components.md`（354 行）

章节：Font Stacks / Type Scale + Weight Mapping / Minimum Readable Sizes / Card Fills（Swiss only，互斥）/ Image Containers / Screenshot Containers / Map Block / Spacing Tokens / Icons / Issue Label and Corner Metadata / Layout Primitives / Hard Rules。

- 组件层的唯一事实来源：字体栈、字号阶梯与字重映射、手机可读下限、中文标题长度带、图片容器比例类、间距 token、Lucide 图标规则。
- 含两张实测上限表：`.h-xl` 各画板硬上限、`.poster.xhs` 上 matrix + hero-stat 的搭配建议。
- 含"主体感知裁切表"（主体位置 → `object-position` 取值）与 figcaption 类名硬规则（Editorial / Warm Gold `.img-cap`、Swiss `.swiss-img-caption`，**没有共享的 `.cap`**）。
- 改种子模板时必须同步改这里，反之亦然（README 贡献章节）。

### 3.4 `layout-recipes.md`（1023 行，最长文档）

章节：Editorial Magazine × E-ink Recipes / Swiss International Recipes / Warm Gold Recipes / WeChat Adaptation。

- 40 个骨架（`M01-M16` / `S01-S12` / `G01-G12`）的完整 recipe：适用场景、HTML 骨架、文案上限、**Minimum density**。
- 开头有硬性的 Content density rule 与"这些结构适用于任何 topic"的前言。
- M16 含 Photo qualification gate（quiet-zone + light 两关都过才能用）与禁止清单；M03 / M04 / M07 / M13 各有独立的最低密度要求。
- 末尾有 21:9 / 1:1 的适配规则。

### 3.5 `background-systems.md`（174 行）

章节：Layer Model / When To Show WebGL / WebGL Helper / 2D Fallback / Do Not。

- Editorial 的分层背景系统：什么时候挂 WebGL 墨流、什么时候退到冻结的程序化画布 + 纸纹。
- 明确禁止：整页网格 / 点阵背景、纯平色米色底。

### 3.6 `portrait-fill.md`（85 行）

章节：Vertical Zones / Underfilled Page Smells / Fixes For Thin Tables / Fixes For Sparse Text / Fixes For Screenshot Pages / Page Rhythm / Minimum Occupancy。

- 3:4 画板的欠填诊断与修法：短表格、稀疏文字、截图页各自的扩写手段。
- 写 3:4 之前必读。

### 3.7 `content-planning.md`（162 行）

章节：Compression Ladder / Rednote Page Plan Template / Good Page Roles / Copy Rules / Cover Hook Patterns / WeChat Square Title Compression / Image-Led Sequence / Page Count Guidance / Matching Visuals To Content / Captions And Metadata。

- "写什么"的规则：文案压缩阶梯、页面角色、封面钩子模式、页数建议。
- Image-Led Sequence 定义满图序列（P1 M16 → P2 文字数据卡 → P3 副图），硬规则是"绝不连续两张 M16"。

### 3.8 `production-workflow.md`（176 行）

章节：Recommended Folder Shape / HTML、CSS Rendering Pattern / Rendering / Verification Commands / Screenshot Treatment / Generated Images / Accessibility And Readability / Common Fixes。

- 渲染管线的标准做法与命令；任务目录结构。

### 3.9 `image-overlay.md`（152 行）

章节：Rule 1（Selection first, mask only if selection fails）/ Rule 2（Place text away from subject / face zones）/ Checklist before delivery。

- 文字压图四步法：选图门 → 默认不加遮罩 → 兜底用局部同色系软渐变（peak α ≤ 0.30）→ 缩略图测试。
- 明确禁掉全幅 vertical falloff 与纯黑遮罩色；构图纪律为非对称、≥60% 留白、标题只占一个 quiet zone、绝不跨越主体轮廓。

### 3.10 `screenshot-treatment.md`（212 行）

章节：When to reach for it / Subject Prep / Anatomy / Parameters / Device chrome / Safe-area cropping / Style cheat-sheet / Validator。

- 用户给 app / web / code / dashboard 截图时用：选 `.frame-shot` 还是 `.frame-img`、圆角 / 阴影 / 底色 / 内缩怎么定、要不要用 `.device-browser` / `.device-phone` 外壳。
- 含 "Solid `bg-*` vs asset `bg-asset-*`" 对照表与 4 条经验规则（不混 accent、不叠 `shadow-ed`、一致使用、高比例板不用素材底）。

### 3.11 `map-component.md`（148 行）

章节：Three rendering modes / Hard rules / Pin placement playbook / Recipe routing / Tone tokens / Common mistakes。

- 内容有空间关系时（旅行路线、门店分布、步行导览）用。
- 真实路线默认 Mapbox Static 或 OSM 静态瓦片；示意图只用于概念 / 图解；pin 是 HTML 叠加层；**禁止真实 JS 地图**。

### 3.12 `title-shortener.md`（128 行）

章节：Why a separate title is needed / The 5-step extraction / Patterns that work for 1:1 covers / Anti-patterns / Sizing on `.poster.square` / Cross-platform pairing / Workflow integration。

- 做公众号 21:9 + 1:1 封面对、或任何跨平台复用标题时的短标题推导法。

### 3.13 `category-cookbook.md`（258 行）

章节：Live Photo Scene Library / 旅行 / 职场 / 游戏 / 影视 / 美食 / 彩妆 / 健身 / 家居 / 穿搭 / 情感 / 推荐 / Capability Circle Summary。

## 七、文件之间的引用关系

```text
SKILL.md
 ├─ 必读：assets/template-editorial-card.html 或 template-swiss-card.html（Step 4.5 拷贝）
 ├─ 按需读：references/ 16 份（触发条件写在 Required References 段）

                └─ 依赖 playwright 真实渲染

references/layout-recipes.md ── 引用 components.md 的类名与字号
references/style-system.md   ── 与 theme-presets.md 共同定义主题边界
assets/template-*.html       ── 必须与 components.md 的表格一致（README 贡献规则）

scripts/check-skill-docs.mjs ── 断言 SKILL.md / references / PRODUCT.md / HANDOFF.md 的关键段落存在
```

**维护联动规则**（README 贡献章节）：

1. 改种子模板 → 同步 `references/components.md` 的字号 / 字距 / 字重对照表。
2. 新增版式 → 在 `references/layout-recipes.md` 写完整 recipe（含文案上限与 Minimum density）。
3. 新增主题色 → 同步种子模板的 `[data-theme]` 块与 `references/theme-presets.md`。
4. 新增 Swiss 规则 → 同步 `validate-social-deck.mjs` 的对应规则。
5. 踩过的坑 → 写进 `references/qa-checklist.md`。
6. 测试与 demo → 一律放 `local-tests/`。

## 八、产物放置规则（`AGENT.md` + `.gitignore`）

允许留在仓库根目录的只有 skill 本体：`SKILL.md`、README、`references/`、`assets/`、`agents/`、`validate-social-deck.mjs`、`package.json` / 锁文件，以及授权与项目级文档。

一次任务的产物结构：

```text
local-tests/<case-name>/
├── index.html          # 从种子模板拷来，含多个 .poster
├── render.mjs / render.cjs
├── assets/             # 源图、截图、下载素材、SOURCES.md
└── output/             # 渲染出的 PNG / JPEG / MOV / .pvt
```

`.gitignore` 拦下的内容：`local-tests/`、`outputs/`、根目录的 `social-card-*` / `livephoto-*` / `wechat-*` / `output/`、根目录 `*.png` / `*.jpg` / `*.jpeg` / `*.mov` / `*.mp4` / `*.pvt/`、`node_modules/`、`py-libs/`、`__pycache__/`、编辑器目录与日志。**这些护栏的存在意味着：如果某次生成物出现在根目录，它不会被 git 记录，但会污染工作区，属于流程违规。**
