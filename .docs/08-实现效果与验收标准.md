# 08 · 实现效果与验收标准

前面几份文档讲的是"怎么做到"，这份讲"做完是什么样、怎样算做对了"。素材来自 `HANDOFF.md` 里逐版本的**改版前后对比记录**、`SKILL.md` 的硬性门槛与 `PRODUCT.md` 的反模式清单——都是仓库里真实记录过的效果证据。

---

## 一、交付物形态

一次任务的产物只有两类：**PNG**（静态交付）和 **`JPG + MOV + .pvt`**（Live Photo 交付）。没有动效、没有网页、没有部署。

| 产物 | 文件 | 尺寸 | 备注 |
| --- | --- | --- | --- |
| 小红书 / Rednote 组图 | `output/*.png` | 1080×1440 | 一份 deck 常含 3-9 张，逐张 `.poster` 节点导出 |
| 公众号 21:9 | `output/*.png` | 2100×900 | 与 1:1 写在同一个 HTML 内 |
| 公众号 1:1 | `output/*.png` | 1080×1080 | 短标题、默认不放图 |
| Live Photo | `*.JPG` + `*.MOV` | 1080×1440 等 | 小红书 `5s` / 公众号 `3s`（实测样例为 5s / 24fps / 120 帧） |
| Live Photo 发布包 | `*.pvt` | — | `JPG + MOV` 打包，AirDrop 到 iPhone 作为一个整体 |

任务目录结构见 [`07-目录结构与文件清单.md`](./07-目录结构与文件清单.md)。**根目录不许出现生成物**，这是 skill 的硬护栏。

## 二、三块画板各自的视觉构成

| 画板 | 构成方式 | 硬性要求 |
| --- | --- | --- |
| `.poster.xhs`（3:4） | 内容（文字 + 图 + 数据）吃满画布；heros / ledger / 引语列 / 边注 / 图井共同撑起竖版 | 内容覆盖 ≥75% 画布高度；任何 >15% 画布的纯空白带必须有留白理由 |
| `.poster.wide`（21:9） | 完整或近完整标题 + 副标题 + 一个强视觉关系 | 不靠裁切 1:1 得到，单独构图 |
| `.poster.square`（1:1） | 由长标题推导的短标题，大字居中，默认不放图 | 不塞拥挤副标题；短标题推导走 `references/title-shortener.md` |

## 三、真实的效果对比（来自版本历史）

这些是 `HANDOFF.md` 里逐版本记录的实际前后差异，最能说明"这个 skill 认为的好效果是什么"。

### 3.1 封面压字：从"旅游海报"到"Kinfolk 专题"（v0.8 → v0.9）

| | 改版前 | 改版后 |
| --- | --- | --- |
| 遮罩 | 全幅黑色 vertical falloff + 78% 侧栏 scrim | 默认不加遮罩；仅在底部 22%×84% 苔绿色软 radial 支撑标题对比 |
| 字号 / 字重 | 132px 黑体感字 | 92px Noto Serif SC weight 500 |
| 字色 | 纯白 | 纸米 `#f5f1e8`，tracking `0.12em` |
| 读感 | 像旅游打卡海报 | 像杂志专题 |

配套固化的规则：M16 禁用 inline 700+ 字重、禁用纯白 `#fff`、禁标题 > 120px、禁拉丁 sans 作主标题；字号区间收在 88-108px。**缩略图测试**（缩到 360px 宽）是这条效果的验收手段。

### 3.2 3:4 内容密度：从"PPT 漏排"到撑满（v0.10）

| | 改版前 | 改版后 |
| --- | --- | --- |
| 内容分布 | 内容散在画布中段 | 内容撑满到约 92% 画布高度 |
| 底部 | 25%-35% 是空白带 | 引语 + footer 紧贴底缘 |
| 缩略图观感 | 像 PPT 漏排 | 逐张独立成立的社交卡 |

根因被写进文档：**杂志靠对开页吸收留白，社交卡是逐张独立刷的**，所以杂志留白逻辑不能直接搬。禁止用空 `<div style="flex:1">` 上下夹击把内容挤到中段，改用 `flex-grow` + `justify-content: space-between` 让内容块本身撑开。

### 3.3 Editorial 美学：从"信息图横幅"回退到"克制磁带感"（v0.11 → v0.12）

| 元素 | 错误值（v0.10 / v0.11） | 正确值（回到 showcase） |
| --- | --- | --- |
| `.h-display` | 900 字重 / −.01em | 124px **weight 500** / **+.04em** |
| `.h-xl` | 700 / −.01em | 88px weight 500 / +.03em |
| `.lead` | sans-zh | 28px **serif-zh** |
| 观感 | "信息图横幅"塌方 | 杂志感成立 |

这条被写成 Editorial Mode A 的 typography stance：**"the larger, the lighter"** ——大字号必须配细字重、serif 正文、宽字距。同一个原则在 Swiss 上是硬规则：80-120px 的标题配 700-900 字重"不 Swiss"。

### 3.4 交付节奏：从 8-12 分钟压到 3-5 分钟（v0.12）

渲染完先给用户看图，只问一句"先你自己看，还是我先自动核查一遍"，用户说要才跑校验。原因是校验本身常耗 5-10 分钟，而用户的眼睛 30 秒就能扫出问题；校验也测不出"这张图气质塌了"这类问题。

## 四、量化验收标准

| 维度 | 门槛 | 出处 |
| --- | --- | --- |
| 3:4 填充度 | 内容 ≥75% 画布高度 | `SKILL.md` Non-Negotiables |
| 空白带 | >15% 画布高度需留白理由（hero 呼吸 / 单句宣言 / 段落前后留白合计 ≤15%） | 同上 |
| 4 横带密度 | Filled + Justified ≥100%，Filled ≥75%，相邻两带不能都 justified | `references/qa-checklist.md`、校验器 R5 |
| 溢出修正阶梯 | 1-40px 微调 / 40-90px 局部压缩 / 90-160px 轻微压缩 / 160px+ 才换 recipe | `SKILL.md` Non-Negotiables |
| 标题间距 | 主 display 标题下方 ≥28px，局部标题 ≥16px | 校验器 R9 |
| 最小字号 | 不得低于手机可读下限（校验器 R4 按住角色判定） | `references/components.md` |
| `.h-xl` 行数 | 不超过画板预算（xhs 92px / square 78px / wide 96px 等实测上限；校验器 R6 按画板判定，暖金同） | `references/components.md`、校验器 R6 |
| 暖金金面积 | 金渐变覆盖 <60% 画布，只做规则与签名 | 校验器 R10、`references/components.md` |
| 暖金阴影色 | 仅 `rgba(122,74,0,…)` / `rgba(17,9,4,…)`，禁止纯 `#000` + 金光晕 | 校验器 R11、`references/components.md` |
| 缩略图可读性 | 缩到 360px 宽后标题仍可读 | `references/image-overlay.md` |
| Swiss 字重纪律 | 大标题配细字重 | 校验器 R3 |
| 版式漂移 | 无浏览器默认 `<figure>` margin 造成的位移 | 校验器 R7 |
| 视觉边界 | 上下边界不超出画板，且底部不出现异常空白 | 校验器 R8 |
| 照片裁切 | 每张图 inline 指定 `object-position`，人脸 / 关键 UI / 产品细节不被裁 | `SKILL.md` Step 6 |
| 数据真实 | 版本号、报价、百分比不编造 | `PRODUCT.md` 反模式 6 |

校验器 `validate-social-deck.mjs` 用 Playwright 做真实 DOM 测量（不是静态扫描），11 条规则（R1-R11），FAIL 时退出码 1，WARN 为建议。规则细节见 [`06-工具链与脚本.md`](./06-工具链与脚本.md)。

## 五、风格身份判定

交付 Editorial 之前要跑 `references/style-system.md` 的 **Identity Test**：只有 serif 标题**不算** Editorial。以下三条同时成立才算：

1. 至少有一层氛围（纸纹 / 墨洗 / WebGL 冻结画布）；
2. 结构里有杂志构件（ledger 行、边注、pull quote、大图井之一）；
3. 不是"平纸底 + 每行都挂等宽标签 + 无氛围层"的组合。

Swiss 侧对应的是 **Anti-Pattern**：大字号 + 重字重、卡片套卡片、任意装饰 SVG 都直接判不合格。

Warm Gold 侧是 `style-system.md` 的 **Warm Gold identity test**，三条同时成立才算：`data-system="warm-gold"` + 一套 sanctioned palette；衬线标题 + 无衬线正文 + 等宽元数据的混排；至少一个金签名（金规则 / `#B8860B` 光晕 / 金投影 / 金发丝线）。只有象牙底 + 金色点缀、字体单一的是 "Swiss-with-gold / Editorial-with-gold"，不算暖金；金铺满画布直接不合格（R10）。

## 六、视觉参考锚点

`README.md` 列出的参考样本决定了"好效果"的方向：

- *Monocle* / *Kinfolk* / *Cereal* 的版式与字距
- Massimo Vignelli / Helvetica Forever / 瑞士国际主义网格系统
- Apartamento / *The Gentlewoman* 的图文比与人物纪实
- 小红书信息流里"克制反而吃香"的内容样本
- 暖金中登（本 fork 定制）："中登登记纸 + 金墨"的仪式感——象牙纸、浓咖啡墨、金只做规则与签名

`PRODUCT.md` 把"被偏爱的杂志"锚定为：上海译文社的封面、The New Yorker 的内文版式、Apartamento / Kinfolk 的留白节奏、Massimo Vignelli / Helmut Schmid 的瑞士网格。

判断标准被写成一句可执行的话：

> 当你出完一张图，先问：如果用户截屏发给朋友，朋友会不会愿意停下来看。

## 七、已知的效果短板（事实层面的限制）

| 限制 | 说明 |
| --- | --- |
| Editorial 模板未做同等强度的冒烟测试 | M14 纵向 Pipeline 5 步在 3:4 板上是否溢出，文档标注为未验证 |
| Swiss 只覆盖 5 个 recipe 的真实样例 | S01 / S07 / S10 / S11 / S12 跑过冒烟测试，其余未跑 |
| 暖金冒烟为每 recipe 单页 | G01-G12 已在 `local-tests/smoke-warmgold-audit/` 全量通过 validator 与渲染（含 R10/R11 负样例），但未跑多页连贯套图（跨页节奏未验证） |
| 没有跨平台一次出包工具 | 一篇文章同时要出小红书 + 公众号时要开两个任务目录手工做 |
| 品类能力圈未硬编码 | skill 不会自动拒绝能力圈外的品类，依赖执行者主动告知 |
| Live Photo 高光选择只是低成本诊断 | 不承诺精准识别转场、空镜、黑场或最佳高光 |
| Live Photo 发布依赖手机端路径 | 桌面 / 网页上传路径一般不能把 `.pvt` 识别为可发布 Live Photo，需降级为 GIF / 静音 MP4 |
